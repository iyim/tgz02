## 一、任务一：组合故障下不许销毁同步对象

### 1.1 审查指出的漏洞确实存在

```c
/* T8-12.9（错） */
if (!create_ok) {
    for (i = 0; i < ncreated; i++)
        if (pthread_join(th[i], NULL) == 0) njoined++;
    chk(njoined == ncreated, ...);
    chk(njoined == ncreated, ...);
    pthread_mutex_destroy(&st->mu);        /* ← 无论 njoined 是多少都执行 */
```

`--create-fail 2` 单独跑能过，只是因为这 2 个线程的 join 恰好都成功。一旦 `--create-fail 2 --join-abandon 1` 同时生效，`njoined=1 != ncreated=2`，mutex 照样被销毁 —— 上阶段刚消除的危险被组合故障绕回来了。

### 1.2 修复

```c
if (!create_ok) {
    int expect_complete = (g_fail_join_at < 0 && g_join_abandon_at < 0);
    for (i = 0; i < ncreated; i++)
        if (t_join(th[i], i) == 0) njoined++;          /* 可注入：组合故障才能表达 */
    chk((njoined == ncreated) == expect_complete,
        "join 结果符合预期（njoined=%d/%d ...）", njoined, ncreated, ...);

    if (njoined != ncreated) {
        chk(counters_snapshot(st, w, ncreated, 0, &s) == -1, "join 不完整时拒绝读取共享计数器");
        chk(g_mutex_destroyed == 0, "join 不完整时不得销毁 mutex");
        chk(g_destroy_after_all_join == 0, "join 不完整时没有发生任何销毁动作");
        printf("RESULT: INCOMPLETE (checks=%d fails=%d) —— 部分创建后的线程退出状态无法确认\n", ...);
        hard_exit(2);                                   /* 不 return：后续场景一律不跑 */
    }
    pthread_mutex_destroy(&st->mu);                     /* 只有全部 join 完才到这里 */
    ...
}
```

`hard_exit()`（不是 `return`）保证"不得继续执行其他测试场景"；`st` 在堆上、`w[]` 是静态的，所以不 free 也不会被写坏（12.9 那个 SIGSEGV 的教训）。

### 1.3 两个组合都验证了

| 运行 | 结果 | 退出码 | mutex | 计数器 |
|---|---|---|---|---|
| `--create-fail 2` | INCOMPLETE 59/0 | 2 | 已全部 join → 允许销毁（断言 `destroy_after_all_join==1`） | 拒绝读（返回 -1） |
| `--create-fail 2 --join-fail 1` | INCOMPLETE 60/0 | 2 | **未销毁** | 拒绝读 |
| `--create-fail 2 --join-abandon 1` | INCOMPLETE 60/0 | 2 | **未销毁** | 拒绝读 |

```
[PASS] create 部分失败后，已创建线程的 join 结果符合预期（njoined=1/2，join-fail=-1，abandon=1）
[PASS] join 不完整时拒绝读取共享计数器
[PASS] join 不完整时不得销毁 mutex
[PASS] join 不完整时没有发生任何销毁动作
[INFO] 部分创建 + join 失败：线程退出状态无法确认
RESULT: INCOMPLETE (checks=60 fails=0) —— 部分创建后的线程退出状态无法确认
```

`--join-fail` 仍保留"真 join 成功但报告失败"的保守语义，`--join-abandon` 仍是真正弃置线程；两者在组合里表现一致、都可查。

## 二、任务二：冻结后的字节复核（TOCTOU）

### 2.1 新顺序

```
PRECHECK(读原字节) → FREEZE(逐线程) → 二次字节复核 → 停止 PC 检查 → INSTALL → 组读回 → RESUME → verdict
```

`verify_after_freeze()` 在冻结之后、任何 `w_write` 之前重读三个入口，并留下事件序号 `ev_postfreeze_verify`。断言链：

```
I7: ev_freeze < ev_postfreeze_verify < ev_first_store
I7: ev_postfreeze_verify < ev_pc_check
```

### 2.2 检测到外部改动时：不写、不回滚、保留现场

```c
if (verify_after_freeze(w) != 0) {
    (void)resume_all(w);
    w->state = ST_ABORTED;
    decide_verdict(w, 0, 1);     /* V_ENTRY_CHANGED_BY_OTHERS；不调用 rollback() */
    return -1;
}
```

新增 verdict **`V_ENTRY_CHANGED_BY_OTHERS`**：我们一个字节都没写，入口也不是我们的序言，所以**旧快照绝不能写回去**（那会覆盖别人的改动）。回滚函数在这条路径上根本没被调用，`restore_writes` 断言为 0。

### 2.3 三个入口逐一验证（审查要求 1–7 逐条对应）

| 要求 | 断言 | 结果 |
|---|---|---|
| 1 中止安装 | `k != 0`、`state == ST_ABORTED` | PASS |
| 2 不写任何补丁 | `word_writes == 0` | PASS |
| 3 恢复已冻结线程 | `resumed_mask == frozen_mask`、`resume_count == 1` | PASS |
| 4 保留外部字节、不盲目回滚 | `mem[i] == (0xE1A00000, 0xE1A01001)`、`restore_writes == 0` | PASS |
| 5 verdict 不得为 SUCCESS | `V_ENTRY_CHANGED_BY_OTHERS`、`!= V_SUCCESS` | PASS |
| 6 恢复失败必须 RESUME_FAILED | `[S13r]`：外部改动 + 线程 2 不能恢复 → `V_RESUME_FAILED`，且 `resume_failed_mask == TH_BIT(2)` | PASS |
| 7 事件序号证明复核在写入之前 | `ev_postfreeze_verify != 0 && ev_first_store == 0`（本轮从未记录到写事件） | PASS |

实际输出（Linux/NAS）：

```
[S13.1] entry 1 is rewritten by someone else right after the freeze
  [PASS] entries 0..1 were re-read, stopping at the mismatch (2 reads)
  [PASS] the mismatch was detected at entry 1 (1)
  [PASS] no patch word was written at all (0)
  [PASS] the foreign bytes are still there (0xE1A00000 | 0xE1A01001)
  [PASS] no stale snapshot was written back (0 restore stores)
  [PASS] verdict ENTRY_CHANGED_BY_OTHERS (ENTRY_CHANGED_BY_OTHERS)
  [PASS] re-verification ran (2) and no store event was ever recorded (0)
```

测试是**真的改了 `mem[][]`**（`external_write_after_freeze[i]` 在 `freeze_all()` 完成冻结后写入），复核只是读，不存在"加个布尔就断言"。

## 三、任务三：逐线程冻结/恢复

### 3.1 位图模型

```c
unsigned target_mask;        /* 本次目标线程集合（0 = 全部 NTH=4） */
unsigned frozen_mask;        /* 真的停住的 */
unsigned resumed_mask;       /* 真的恢复的 */
unsigned resume_failed_mask; /* 恢复失败的 */
```

```c
static int freeze_all(world_t *w) {
    ... for (i = 0; i < NTH; i++) {
        if (!(target_mask & TH_BIT(i))) continue;
        if (f.freeze_fail_at == i) return -1;      /* 第 i 个失败，前面的是真停住的 */
        frozen_mask |= TH_BIT(i);
    }
}
static int resume_all(world_t *w) {
    if (frozen_mask == 0) return 0;                /* 没冻过就不恢复 */
    for (i ...) {
        if (!(frozen_mask & TH_BIT(i))) continue;  /* 只恢复被冻结的 */
        if (f.resume_fail_at == i) { resume_failed_mask |= TH_BIT(i); rc = -1; continue; }
        resumed_mask |= TH_BIT(i);                 /* 尽力而为：一个失败不阻止其他 */
    }
}
```

"至少冻结了一个线程"不再被当成"全部冻结"。新不变式 **I9**：

```
frozen_mask ⊆ target_mask
resumed_mask ⊆ frozen_mask
resume_failed_mask ⊆ frozen_mask
resumed_mask ∩ resume_failed_mask = ∅
(frozen_mask && resume_count==1) ⇒ (resumed_mask | resume_failed_mask) == frozen_mask
freeze_count == 1 时，除非注入了 freeze 故障，frozen_mask 必须等于 target_mask
```

### 3.2 七组场景（审查列出的 1–7）

| 场景 | 内容 | 断言要点 | 结果 |
|---|---|---|---|
| `[S14.0]` | 全冻结、全恢复 | `frozen == target`、`resumed == frozen`、`failed == 0`、SUCCESS | PASS |
| `[S14.1.1..3]` | 第 N 个线程冻结失败 | `frozen == (1<<N)-1`、**`frozen != target`**、`resumed == frozen`、0 次字写、INSTALL_FAILED | PASS |
| `[S14.2]` | 冻结失败 + 其中一个已冻结线程恢复失败 | `resumed={1}`、`failed={0}`、两者并集 == frozen、`V_RESUME_FAILED`、既非 INSTALL_FAILED 也非 SUCCESS | PASS |
| `[S14.3]` | 全部冻结、线程 1 恢复失败 | `resumed == target \ {1}`、`failed == {1}`、`V_RESUME_FAILED` | PASS |
| `[S14.4]` | 安装失败、回滚成功、逐一恢复 | `resumed == frozen == target`、INSTALL_FAILED | PASS |
| `[S14.5]` | 安装失败、回滚失败、逐一恢复 | `resumed == frozen`（回滚失败也不许把线程留在冻结态）、ROLLBACK_FAILED | PASS |
| `[S14.6]` | 4 个单线程恢复失败扫描 | 任一位置都不得出现 SUCCESS/INSTALL_FAILED，`failed` 精确、frozen 全部有归属、resume 只做一次 | PASS |

### 3.3 顺带修掉的返回值缺陷

`install_all()` 原来 `return install_ok ? 0 : -1;` —— 安装成功但恢复失败时返回 0。现在：

```c
/* 0 means "the transaction really succeeded", i.e. V_SUCCESS only */
return (w->verdict == V_SUCCESS) ? 0 : -1;
```

`[S10]`（装好但恢复失败）的断言也随之从"返回 0"改为"返回非零"，同时保留"三个入口确实是补丁态"的字节断言。

## 四、任务四：构建脚本不再可能跑旧二进制

`run_nas3.sh` 重写为硬失败驱动：

| 机制 | 实现 |
|---|---|
| 清空旧产物 | `rm -rf "$D"; mkdir -p "$D"` + `rm -f ./*.txt ./*.log ./*.exe` |
| 每个编译失败即终止 | `if ! gcc ... ; then build_fail "..."; fi`，`build_fail` 写 `STATUS.txt`/`DONE.txt` 后 `exit 1` |
| 工具链缺失即终止 | apt 返回码检查 + `command -v gcc` |
| 只跑本轮产物 | `: > "$D/.build_start"` 时间戳 + `need_fresh()` 用 `[ "$1" -nt .build_start ]` 判定，缺失或过期一律 `build_fail` |
| 明确结论 | `STATUS.txt` = `TEST PASS` / `INCOMPLETE: ...` / `BUILD FAILED: ...`；另有 `SUMMARY.txt` 汇总四个 RESULT 行与两处 TSan 计数 |
| 不把旧结果当本轮 | 每次运行前整个输出目录被删；且 `TEST PASS` 只有在 4 个 `RESULT: PASS` + `tsan_normal races=0` + `tsan_race_true races>0` 同时成立时才给出 |

本次 `STATUS.txt`：**`TEST PASS`**；`BUILD.txt`：`BUILD_PASS`；`SUMMARY.txt`：

```
BUILD PASS
plain_normal RESULT: PASS (checks=71 fails=0)
tsan_normal  RESULT: PASS (checks=71 fails=0)
fsm_normal   RESULT: PASS (checks=1157 fails=0)
fsm_tsan     RESULT: PASS (checks=1157 fails=0)
tsan_normal races=0
tsan_race_true races=1
```

诚实说明：**"旧二进制被拦截"这条路径本身没有被实际触发**（触发它就会中断正常跑）。机制是 `need_fresh()` 里 3 行 `-nt` 比较；若把 `.build_start` 更新到比二进制还新，下一次运行必然 `BUILD FAILED`。
