## 一、退出码修正

```sh
# 旧：无论写什么状态都 exit 0
finish() { printf '%s\n' "$1" > "$D/STATUS.txt"; ...; exit 0; }

# 新
finish() {
    status=$1
    rc=$2
    printf '%s\n' "$status" > "$D/STATUS.txt"
    printf '%s\n' "$status" > "$D/DONE.txt"
    chmod -R a+rX "$D" 2>/dev/null
    log "$status"
    exit "$rc"
}
...
if [ "$fails" -eq 0 ]; then
    finish "TEST PASS" 0
else
    finish "INCOMPLETE: see SUMMARY.txt (a required PASS or control condition did not hold)" 2
fi
```

`build_fail()` 保持 `exit 1`，三个码互不重叠：**0 = 全部验收通过，1 = 构建/工具链失败，2 = 跑完但验收不通过（含日志缺失）**。

## 二、逐项验收门禁

判据函数（按审查建议实现，另加数值判据与"缺文件"判据）：

```sh
require_file()   { [ -s "$1" ]; }
require_result() { grep -q "^$2" "$1"; }              # $2 = RESULT 前缀
require_exit()   { grep -q "^EXIT=$2\$" "$1"; }
require_races()  { grep -q "^TSAN_RACE_WARNINGS=$2\$" "$1"; }
require_no_pass(){ ! grep -q '^RESULT: PASS' "$1"; }
require_races_gt0() {                                  # 数值判断，不是字段存在
    n=$(grep -h '^TSAN_RACE_WARNINGS=' "$1" | cut -d= -f2)
    [ -n "${n:-}" ] && [ "${n}" -gt 0 ]
}
```

门禁项（每一项独立计分，任一不过 → 整体 INCOMPLETE）：

| 组 | 内容 | 项数 |
|---|---|---|
| **A** 正常主跑 | `plain_normal` RESULT PASS + EXIT=0；`tsan_normal` 三项（PASS/0/races=0）；`fsm_normal` 两项；`fsm_tsan_run` 三项 | 10 |
| **B** 负向对照 | `plain_race_control` FAIL+1；`tsan_race_control` FAIL+1+races=0；`tsan_race_true` **races>0** + EXIT=66 | 7 |
| **C** 五种 INCOMPLETE ×2 构建 | `create_fail` / `create_fail_join_fail` / `create_fail_join_abandon` / `join_fail` / `join_abandon`，每个都查 plain 与 TSan 的 `RESULT: INCOMPLETE`、`EXIT=2`、**不得出现 `RESULT: PASS`** | 30 |
| **D** 日志存在 | 18 个必需日志文件非空 | 18 |

> 审查里先写"六类 INCOMPLETE"后更正为"五种模式"，脚本按**五种**实现（`create_fail`、`create_fail_join_fail`、`create_fail_join_abandon`、`join_fail`、`join_abandon`），每种两个构建共 10 个运行、30 项检查。

## 四、退出码实测（三种调用，全部真实执行）

驱动脚本 `run_nas_verify.sh` 连续调用 `run_nas3.sh` 三次，并记录每次的 shell 退出码。两个模拟都在**独立副本**里跑（`/work/sim_gate`、`/work/sim_build`），交付源文件与正式证据 `/work/v5` 不受影响。

| 运行 | 做法 | STATUS.txt | 退出码 |
|---|---|---|---|
| 1 全量正常 | 直接跑交付脚本 | `TEST PASS` | **0** |
| 2 验收失败模拟 | 副本里把正对照的 `--race-true` 去掉，使其无法产生 TSan 报警 | `INCOMPLETE: see SUMMARY.txt (...)` | **2** |
| 3 构建失败模拟 | 副本里给 `SRC` 放一份故意写坏的生命周期源码 | `BUILD FAILED: gcc model_plain` | **1** |

实测原文（`evidence/t8-12-p11/VERIFY_SUMMARY.txt`）：

```
=== exit codes
run1_full_run MAIN_RC=0
run2_gate_failure GATE_SIM_RC=2
run3_build_failure BUILD_SIM_RC=1

=== status files
run1 STATUS: TEST PASS
run2 STATUS: INCOMPLETE: see SUMMARY.txt (a required PASS or control condition did not hold)
run3 STATUS: BUILD FAILED: gcc model_plain

=== run2 failing gate items (proof the gate really fired)
FAIL  B tsan_race_true has >=1 TSan report
FAIL  B tsan_race_true EXIT=66

=== run3 build log tail
/work/sim_build_src/t8_12_9_lifecycle_model.c:917:9: error: unknown type name 'deliberately'
```

第 2 次最有说服力：**状态文件与退出码一致地变成失败**，而且失败项精确指向"正对照没有产生 TSan 报警"—— 说明 B 组门禁不是装饰。第 3 次证明编译失败会在 `gcc model_plain` 处立即终止、返回 1，不会带着旧二进制继续跑。
