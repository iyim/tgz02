# T8-14.1 技能调度器接入 AI Worker（首个真实技能闭环：time.query）

- 基线提交：`6fcb32cf59b93a0f7908425559426534b5b927d3`（T8-13.5）
- 目标：结束"技能注册表只有接口、没有生产调用"的状态，让 `skill_dispatch.c/.h` 在 Worker 里**真的执行**
  一次，结果走既有 TTS 队列与消费一致性；同时原厂路径**默认完全不变**。
- 本轮只接管 `time.query` 一个技能。音量/媒体/屏幕/停止**一律不接管**，仍由原厂执行。

---

## 一、接入前确认的现有接口（未猜字段、未另造队列）

| 接口 | 位置 | 实际形态 |
|---|---|---|
| `t8_skill_registry` / `t8_skill_req` / `t8_skill_result` | `skill_dispatch.h` | id + argc/argv（结构化参数）+ session；结果 = code + message |
| `t8_skill_execute()` | `skill_dispatch.c` | 未注册 -> `T8_SK_E_NOIMPL`，成功/失败分别计入 ok/fail |
| `t8_skill_from_intent()` | `skill_dispatch.c` | 复用 `intent_route` 的分类结果（IR_TIME/IR_VOLUME/…），不重新识别文本 |
| `t8_skill_time_exec()` | `skill_dispatch.c` | 无副作用，`message = "now HH:MM"`（96 字节上限） |
| Provider 回复结构 | `provider.h` | `t6b_reply{status,code,message,text,text_bytes,latency_ms,mock}` |
| TTS 入队 | `ai_worker.c: tts_enqueue()` | 按 `event_id` 幂等；返回 1/0/-1，`out_stage` 给出 queue/inflight/done/failed |
| 状态文件 | `worker_status.c/.h` | 每个模块一个 JSON 对象（`route`/`gate`/`session`/`session_ctrl`…），只放计数与短标签 |
| 构建 | `build_t7_05.ps1`（ARM32）、`tests/run_*.ps1`（host） | `$WorkerSources` 明确列举源文件 |

**没有**新增 TTS 队列、没有新增消费进度格式、没有改动 `intent_route` 的分类规则。

## 二、修改（逐项对应任务书 §三/§四）

### 1) 配置开关（默认关闭）

- `t6b_config` 新增 `int skill_dispatch`（`ai_worker.h`），默认 **0**（`t6b_config_defaults`）。
- `worker.conf` 键：`skill_dispatch_enabled=0|1`（`worker_conf.c` 读/写各一处）。
- 启动日志一行可核对：`skill dispatch: enabled=%d registered=%d time_query=%d`。

关闭时 `skill_claim_id()` 第一句就返回 0 → 路由判定与此前**逐字节一致**。

### 2) 注册表 + 唯一注册项

```c
t8_skill_registry_init(&w.sk);
t8_skill_register(&w.sk, T8_SK_TIME_QUERY, t8_skill_time_exec, NULL);   /* 只有这一个 */
```

注册失败会打日志并保持"不接管"（注册表为空 → 永不接管）。

### 3) 路由：只在"开 + 已注册 + 参数完整"时接管

`uttq_pop_to_pend()` 里，完整 utterance 到手后先做**一次** `ir_classify`，然后：

```c
sk_id = skill_claim_id(w, slot->session, &ir, classified, &sk_req);
if (sk_id == 0 && w->cfg.route_native && classified && route_intent_enabled(w, ir.intent)) {
    ... 原厂路由分支（未改）...
}
```

`skill_claim_id()` 四个条件缺一不可：① 开关开；② 意图位启用且 `ir.complete`；
③ `t8_skill_from_intent` 能翻译；④ **该技能已注册**。未注册一律回落原厂/AI ——
所以生产路径上**不可能**出现 NOIMPL（NOIMPL 契约由注册表单测覆盖）。

接管时日志 `route=skill skill=time.query event=… rule=… arg=…`，
并在状态里记为 `skill_dispatch.claimed++`，**不**计入 `route.ai`（那是"交给大模型"的计数）。

### 4) 执行：技能就是这一轮的"Provider"

`provider_attempt()` 开头分流：`w->pend_skill_id != 0` → 由 `skill_run()` 执行技能，
把 `t8_skill_result.message` 填进 `t6b_reply.text`（`status=T6B_P_OK`）；
否则走原来的 `cv_build_messages` + `t6b_provider_complete_msgs`。

复用点（一行未改）：`tts_enqueue()`（含 event_id 幂等与四阶段判定）、`ef_note_enqueue()` 回声登记、
`cs_on_queued()`/`sc_on_tts_queued()` 会话状态、`commit_event()` 消费一致性、重试/退避/死信。

技能成功计数进 `sk_ok`，不混入 `provider_ok`（观测上分得清谁回答的）。

### 5) 失败语义（明确、不伪造、不双答）

技能返回非 OK（或返回空文本）→ `rep.status = T6B_P_ERROR`，走**既有** Provider 失败尾部：
`provider_err++`、`sc_note_timeout()`、按退避重试、超过 `provider_retry_max` 报 stuck、
再超 `T6B_DEAD_LETTER_EXTRA` 次进死信（`dead_letter.jsonl`，可读、可恢复）。

因为接管时**没有**写原厂放行标记、也**没有**进大模型，所以失败时不存在"原厂和 AI 都回答一遍"。
**回退策略的选择与理由**：不把失败的事件"事后"改投原厂 —— 原厂放行标记是"对下一条 utterance
生效的令牌"，事后补写可能让原厂去回答**另一句**话，风险比"这句话这次没答"更大。
因此失败路径是"重试 → 死信可见 → 人工/后续轮次恢复"，而不是"悄悄换条路答一遍"。
（`provider_dead_letter=0` 的"永不跳过"模式同样适用：事件原地堵住，绝不静默丢弃。）

### 6) 同一 event_id 重放：先探测，再决定要不要执行

新增只读探测 `tts_probe_stage()`（不建目录、不 fsync、不写）：在**执行技能之前**检查该 event_id
是否已存在于 TTS 队列的 queue/inflight/done/failed 任一阶段。命中则 `sk_dedup++`、**不执行技能**、
不入队、按成功终结并推进消费 —— 跨进程重扫（重启后 offset 归零重读同一 event）也不会重复执行、
不会重复播报。`tts_enqueue()` 既有的幂等仍是第二道闸。

### 7) 状态与日志（只放计数/短标签，无正文）

新增 `"skill_dispatch":{enabled,calls,ok,fail,noimpl,claimed,dedup,last_skill,last_result}`。

日志：`skill ok: skill=… event=… code=OK took=Nms reply_bytes=N`、
`skill FAILED: skill=… code=…`、`skill tts queued: skill=… event=…`、`skill skip (already enqueued stage=…)`。
不含用户正文、不含参数原文、不含密钥。

## 五、本轮未做（明确边界）

- **未上真机、未重启 `:core`**（任务书要求）。因此"技能播报在设备上真的响"仍是**待验证**项：
  设备侧需要在 `worker.conf` 置 `skill_dispatch_enabled=1` 后跑一轮"现在几点"，
  观察 `tts/queue/<event>.json` 被 TtsExec 消费、`play.public.json` 出现 `playing→idle`、
  `session_ctrl` 走 SPEAKING→FOLLOWUP。属下一轮上机验证。
- 未接管音量/媒体/屏幕/停止/天气/退出：`skill_claim_id()` 只因"已注册"而接管，注册表里只有 time.query。
- 未给 PROCESSING 增加通用超时（T8-13.5 结论保留）。
- 没做技能参数化（本轮 `time.query` 无参数）；将来的带参技能在 `skill_run()` 里用
  `t8_skill_req_arg()`，参数只来自 `intent_route` 的结构化结果。
