## 一、P0 修复对照

### 1. 迁移幂等（必须修复）✅
- 新增 `migration` 标记表；**数据插入 + 标记写入在同一个 SQLite 事务**，`endTransaction`
  崩溃即回滚；文件归档（改名 `.imported`）只在事务提交后执行。
- marker 存在但文件仍在（提交后归档失败/中断）→ 跳过导入并归档残留。
- 修复 pre-R1 可能留下的半截导入：导入事务内先 `delete` 全表再从文件重放（迁移窗口内
  文件是唯一事实源；迁移完成后数据受 marker 保护）。
- 真机验证（`evidence/t9-ui-03-r1/`）：
  - 正常迁移：2 条旧闹钟入库 + `.imported` + 快照发布 + T9DATA 日志（15:12:40）
  - **归档失败模拟**：恢复文件名（marker 在）→ 重启 → 跳过导入、文件归档、仍恰好 2 条
  - 中断重试路径：事务回滚语义由 SQLite 保证；marker 缺失时 delete+reimport 产出行数恒等于文件条数

### 2. 快照发布可靠性（必须修复）✅
- `publishXxx()` 检查 `exportSnapshot` 返回值，失败写 `Log.w` 并置 `snapOk=false`；
- 发布串行化（`publishLock`），tmp 文件不可能互相覆盖；
- **启动时全量发布**：`DataService` 构造 + `ensureSnapshots()`；失败在下次变更/下个页面
  打开时自动重试（收敛式）；`snapshotsHealthy()` 供页面区分"DB 已存 vs 快照未同步"。
- 真机验证：删除三份快照 → 重启 → 全部自动再生成（含空数据快照）。
- 顺带修复 R1 过程中发现的真实缺陷：**DataService 此前只在打开记忆中心时才初始化**——
  已移到 `Tgz02App.onCreate`，保证迁移与快照在进程启动即完成。

### 3. 技能状态字段语义 ✅
- `skillSetEnabled()` 只改 `enabled` + `state`（'on'/'off'），禁用不再写 'on'；
- `last_used_ms` 只由 `skillTouch()`（真实使用）更新，开关变化不再触碰；
- 快照 `state` 字段随之正确。

## 二、P1：记忆语音交互 ✅

- **新增记忆的语音路径**（不弹键盘）：孩子说「天猫精灵，记住我不喝咖啡」→ 原厂 ASR →
  turn 事件 → UI 侧旁路识别（仅"记住/帮我记住/记一下"前缀句式）→ **pending 记忆入库
  （enabled=false，宁可不命中不可错误命中）** → 通过 `kind=say`（复用既有 inbox 与原厂
  TTS，**零协议改动、零新语音引擎**）让布丁亲口确认。
- 确认闭环：记忆中心待确认区「记住它/不记了」→ 生效/删除 → 快照同步。
- 键盘输入降级为辅助（对话框仍在，供家长手动补录），不再是新增记忆的主交互。

**真机全链路证据**（journal + 快照 + 截图）：
```
ask  ui3r1m3  "记住我不喝咖啡"   → 原厂回答照常（stub-doubao:ok，AI 管线未被劫持）
say  ui-...-2ab8 (105B)          → 布丁确认语（"好的，我快要记住了：不喝咖啡…"）
snapshot: {"pending":1, "text":"不喝咖啡", "tag":"偏好", "src":"对话学习", "enabled":false}
UI 确认 → toast「已记住」 → snapshot: {"enabled":1, "pending":0}
```
截图中可见 turn 卡片同时显示模型回答（stub-doubao:ok）——学习是**旁路**，不改变回答行为。
