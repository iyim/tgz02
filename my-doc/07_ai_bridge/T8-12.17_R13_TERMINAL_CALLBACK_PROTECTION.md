## 0. 结论

`tg_nlp_cb` 此前**忽略 `type`、忽略 `res==NULL`**，在 DECIDE 模式下 type=3 收尾通知会被送进会话表判定、
FAILCLOSED 模式下会被直接丢弃 —— 这正是 R13。本轮修掉了：

1. **type=2 / type=3 无条件放行**，优先级高于 DECIDE 与 FAILCLOSED，不查表、不进降级窗口、不计普通 NLU 判定；
2. **观测新增 `resnull` 字段**（只比较指针 `res==NULL`，不解引用、不记文本）；
3. 新增 `term_pass` 计数器（收尾放行次数），并把 `resnull` 写进每条观测记录；
4. type=0 与其它未识别 type 的既有判定逻辑**一行未变**。

验证：主机 86 项检查全 PASS；ARM32 NDK 构建 0 warning / 0 error；真机 6 条回调全 type=0、`resnull=0`（res 非空，符合预期）；takeover 全程 0；补丁已卸、入口字节复核原厂。

## 1. 改动（只有 `hook_agent/libtg_hook.c`，+32/−8）

### 1.1 回调判定（R13 核心）

```c
static int tg_nlp_cb(void *self, int sid, int type, void *res)
{
    ...
    int res_is_null = (res == NULL) ? 1 : 0;

    (void)self;

    /* R13: 收尾通知无条件放行，先于任何接管判定 */
    if (type == 2 || type == 3) {
        obs_record(sid, type, nlu_mode_now(), 0, res_is_null);
        INC(g_nlu_terminal_pass);
        return 0;
    }

    mode = nlu_mode_now();
    if (mode == NLS_PASS) { obs_record(sid, type, mode, 0, res_is_null); return 0; }
    INC(g_nlu_nlp_calls);
    if (mode == NLS_FAILCLOSED) { INC(g_nlu_nlp_failclosed); obs_record(sid, type, mode, 1, res_is_null); return 1; }
    ... drop = t8_to_should_drop(...); ...
}
```

要点：
- 收尾分支放在**最前**，因此 DECIDE/FAILCLOSED 都不可能吞掉 type=2/3；
- 收尾分支不 `INC(g_nlu_nlp_calls)` → 旧不变量 `nlp_calls == nlp_pass + nlp_skip + nlp_failclosed` 保持成立；
- 其它 type（0 及未识别）原样走既有判定，语义不变。

### 1.2 观测记录

## 6. type 语义结论（本轮最终口径）

| type | 语义 | 接管判定 |
|---|---|---|
| 0 | 普通 NLU 技能结果（`NlpResult` 非空） | 走既有 DECIDE 判定，语义不变 |
| 2 | `exitTalk` 合成结果 | **无条件放行**，不查表 |
