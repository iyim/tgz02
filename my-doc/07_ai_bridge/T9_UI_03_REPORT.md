| 图片/音频 | APK assets/ | 保持（DB 只存路径类元数据） |

### 分层与访问控制

```
V2 UI（五个一级页面）
   ↓ 只调 DataService，不写 SQL
DataService（App 内统一数据服务：DAO + 校验 + 快照发布 + 迁移）
   ↓ SQLite（WAL）
tgz02.db（App 私有目录，App uid 独占）
   ↓ 变更后原子导出（tmp+fsync+rename）
/data/local/tmp/t9_ui/snapshots/{memory,alarms,skills}.public.json
   ↑ worker（root）只读快照，永不打开 SQLite
```

- **worker 零 SQLite 依赖**（ARM32 体积敏感，framework SQLite 由 Android 提供）；未来
  记忆注入对话时 worker 读 `memory.public.json` 快照（与 status.public.json 同模式）。
- 快照目录 `snapshots/` 由一次性部署脚本创建并 chown 给 App uid（与 inbox/ 同先例）。
- WAL 已启用（`tgz02.db-wal/-shm` 设备上可见）；版本迁移集中在 `Db.onUpgrade`（v1 首版）。

### 明确禁止并已执行

- 不再为任何新功能创建独立 JSON 作为正式数据库（DataService 是唯一入口）。
- UI 不写 SQL（页面只调 DataService）。

## 五、诚实说明

1. **待确认流的产生端缺失**：pending 记忆由"对话学习"产生，学习逻辑属 T9-08D。当前
   UI 的确认/拒绝按钮已实现并可运行，但设备上没有自然产生的 pending 记忆可供点按
   （不造假数据）。T9-08D 接入学习端后此闭环用真实数据验收。
2. IME 干扰：adb 自动化输入被设备拼音 IME 转写（"tea only"→"特啊"），导致验证文本
   出现转写痕迹；功能等价性不受影响（DB 层对语种无差异），中文输入的手工验收点留给
   真人操作。
3. 闹钟到点响铃未实现（诚实标注在页面上），属 T10 技能执行系统。
4. 记忆注入对话（回答时参考记忆）属 T9-08D 的对话侧改造，本阶段只完成存储、管理面与
   worker 可读快照，未擅自改 prompt 结构。
