| 数据 | 路径 | 权限 | 实测值 | 结论 |
|---|---|---|---|---|
| 电池电量 | `/sys/class/power_supply/battery/capacity` | `-r--r--r-- root root`（`adb shell` 非 root 也能读） | **100** | **可用** |
| 电池状态 | `/sys/class/power_supply/battery/status` | 同上 | `Charging` | 可用（本轮不播报，仅作判读） |
| 系统运行时长 | `/proc/uptime` | `-r--r--r-- root root` | `109800.01 129653.72`（第 1 字段 = 秒） | **可用** |
| 交叉核对 | `dumpsys battery` | shell 可读 | `level: 100 / scale: 100`，`AC powered: true` | 与 sysfs `capacity` 一致 |

- 电源节点全集：`ac / battery / usb / wireless` —— 只有 `battery` 有 `capacity`，所以候选列表以它为首选。
- **稳定性**：连续 3 次读取，`capacity` 恒为 100，`uptime` 单调递增（差值 ≈ 0.4 s / 读）——数据源稳定，
  确实是设备实时状态，不是常量文件。
- **不可用的项（明确标不支持）**：`dumpsys battery` 的 `Charge counter = 0`、`Max charging current/voltage = 0`
  （本机 BMS 未上报），因此**不做毫安时/充电功率播报**，避免把 0 当成真实值。
- 口径说明：`/proc/uptime` 是**整机开机时长**，不是"本次对话"或"AI 服务"的运行时长；播报文案用"已运行"，
  不含"本次""刚刚"这类会误导的词。

证据：`evidence/t8-14.2/device_sources.txt`。

## 二、实现

### 1. 技能本体（`skill_dispatch.h/.c`）

```c
typedef struct {
    char battery_path[T8_SK_PATH_MAX]; /* 空 = 自动探测 */
    char uptime_path[T8_SK_PATH_MAX];  /* 空 = /proc/uptime */
} t8_dev_ctx;

void t8_dev_defaults(t8_dev_ctx *c);
int  t8_dev_detect_battery(t8_dev_ctx *c);
int  t8_skill_device_status_exec(const t8_skill_req *req, t8_skill_result *res, void *ctx);
```

- 新增技能 id `T8_SK_DEVICE_STATUS = 11`，名称 **`device.status`**；`T8_SK_MAX` 11 → 12。
- 电池候选：`battery/capacity` → `bms/capacity` → `BAT0/capacity` → `battery/capacity_raw`
  （真机命中第一个；探测不到就按"无电池数据"降级）。
- 读值规则（**不允许脏值进播报**）：
  - `sk_read_int()`：只接受"可选空白 + 十进制整数 + 可选空白"，且必须在 `[0,100]`；
    `101 / -5 / abc / 空文件 / 文件不存在` 一律视为**不可用**。
  - `sk_read_uptime_secs()`：`strtod` 解析首字段，必须 ≥ 0 且 < 1e9（≈31 年，挡垃圾数据）。
- 播报文案（简短、自然，`T8_SK_MSG_MAX=96` 字节内）：
  | 可用数据 | 文案 | 示例（真机值） |
  |---|---|---|
  | 电量 + 时长 | `电量 %d%%，已运行 %s` | `电量 100%，已运行 1 天 6 小时` |
  | 仅电量 | `电量 %d%%` | `电量 100%` |
  | 仅时长 | `已运行 %s` | `已运行 2 小时 10 分钟` |
  | 都不可用 | —（返回 `T8_SK_E_CTX`，`res->code` 同步置位） | `device status unavailable` |
- 时长格式：`≥1 天 → "N 天 M 小时"`（M=0 时省略）、`≥1 小时 → "N 小时 M 分钟"`、否则 `"N 分钟"`。
- 不建新队列、不调原厂私有接口、不写任何文件、不改系统状态（纯读）。

### 2. Worker 接线（`ai_worker.c/.h`）

- `t8_skill_register(&w.sk, T8_SK_DEVICE_STATUS, t8_skill_device_status_exec, &w.dev)`
- `w.dev` 初始化：`t8_dev_defaults()` → 若 `skill_device_battery_path` 非空则用它，否则 `t8_dev_detect_battery()`。
- 启动日志新增一行，路径与开关都可核对：
  `skill device.status: switch=%d battery=%s uptime=%s`
- 复用 T8-14.1 的全部机制：`skill_run()` → `t6b_reply` → `tts_enqueue()`（event_id 幂等）→
  `commit_event()`；`tts_probe_stage()` 的"已说过就不再执行"探测同样生效。

### 3. 配置（默认关闭，双闸）

```ini
skill_dispatch_enabled=0        # 总开关（T8-14.1）
skill_device_status_enabled=0   # T8-14.2 独立开关
skill_device_battery_path=      # 可选覆盖（空 = 自动探测）
```

- 总开关关闭 **或** 技能开关关闭 → `skill_claim_id()` 返回 0，路由行为与 T8-14.1 完全一致
  （设备类问句照旧交给模型，不再被任何人接管）。
- `worker.conf` 写入（`wc_write`）也带上了这三个键，示例文件与设备现状一致。

### 4. 状态（`worker_status.c/.h`）

`skill_dispatch` 对象新增 `"device_status":0|1`；其余计数（calls/ok/fail/noimpl/claimed/dedup/last_skill/
last_result）沿用。技能成功时 `last_result = ok:device.status`，降级失败时 `fail:device.status`。

## 三、真实意图（新增 `IR_DEVICE_STATUS`）

`intent_route.h/.c`：新增 `IR_DEVICE_STATUS = 9`，**故意不分配 route 位**（`ir_route_bit()` 返回 0）——
这是原厂没有的能力，所以它永远不会被"放行给原厂"，只可能是自有技能接管或回落模型。

匹配器 `ir_match_device_status()`，分类链里插在**时间之前**（"设备运行时间是多少"含时间命中词
`时间是多少`，排在后面会被误判成问时间）。

| 类别 | 词 |
|---|---|
| 电量 | `电量 / 电池 / 多少电 / 剩多少电 / 还有多少电 / 还剩多少电 / 几格电 / 剩余电量 / 电量还剩 / 电量还有 / 电量多少` |
| 时长 | `运多久 / 运了多久 / 运多长时间 / 运时间`（+ `运行多久 / 运行时间` 冗余）、`开机多久 / 开机时间 / 工作多久 / 开多久 / 开了多久` |
| 否决 | `电压 / 电流 / 电费 / 功率 / 充电器 / 充电线 / 电阻`（电学量）、`充电宝 / 手机 / 笔记本 / 电动车 / 耳机 / 灯泡`（别的设备）、`推荐 / 买 / 价格 / 多少钱 / 哪个好`（挑商品）、`什么意思 / 为什么 / 原理 / 怎么算 / 区别 / 知识 / 怎么办 / 怎么修 / 坏了`（问知识）、`运输 / 快递 / 物流 / 发货 / 配送` |

**实机前踩到的坑（已修）**：匹配跑在**规范化之后**的文本上，而 `ef_strip_fillers` 会把语气词"行"整字删除 ——
`运行多久` 变成 `运多久`、`运行时间` 变成 `运时间`，原词表完全命中不了。词表因此改为
"规范化后仍能命中"的形式（`运多久 / 运时间 / 运了多久`），原始写法只作可读性冗余。这个坑在主机上是
第一次跑真机意图探针时发现的（`音箱运行多久了` 命中 0）。

## 五、限制与边界

- **本轮不上真机**：设备端还没跑过 `device.status`。真机预期文案（按实数）：
  `电量 100%，已运行 1 天 6 小时`（uptime 109800 s ≈ 1.27 天）。是否真的响、TtsExec 是否照常消费，
  留待 T8-14.2D。
- 电量粒度为 1%（`capacity` 整数）；本机 `Charge counter` 恒 0，因此不做 mAh 播报。
- `/proc/uptime` 是整机开机时长；重启后从 0 开始，不代表历史累计。
- 只有 `battery` 节点上报 capacity；换设备/换内核时路径可能不同（候选列表 + 配置覆盖已覆盖这种情况）。
- 未接管音量/媒体/屏幕/停止/天气/退出/时间；未动 KWS/ASR/R13/Hook；未重启 `:core`。
- 与 T8-14.1 相同的既有事项未变：`run_host_tests.ps1`、`t7_04_gate_unit_test` 属旧套件缺依赖/预期过时，
  本轮同样未改它们。
