# T8-12.20 — 退出意图最小修复与回归

基线 `b07e2c3b`（T8-12.19）。本轮实现审查批准的 §4 最小退出修复，打通 DECIDE 接管下的原厂退出链路。

**边界遵守**：不操作真机、不部署、不重启 `:core`；不改 R13/R13-01、不改 hook 汇编桩、不改原厂函数、不动 stop/volume/其它意图分类的既有规则、未扩大退出关键词范围。

## 一、修复内容

### 1.1 核心缺陷修复（DECIDE 下"退出"被 DROP）

缺陷链（T8-12.19 已定位）：`ir_classify("天猫精灵退出")` → `IR_NONE` → `why=AI` → 登记 → `t8_to_should_drop=1` → `tg_nlp_cb` 返回 1 → 原厂 `onNlpResult` 主体被跳过 → `SessionManager::exitTalk`（type=2 合成入口）永远走不到。

修复 = 新增退出意图，让明确退出短句在 DECIDE 下返回 **PASS**（原厂自己识别退出语并执行 exitTalk）：

- `intent_route.h`：`IR_EXIT = 8`（枚举追加，不动既有值）+ `T7B_ROUTE_EXIT 0x80`；**`T7B_ROUTE_ALL 0x7F → 0xFF`**。
- `intent_route.c`：`ir_match_exit()` —— **整句精确匹配**（不是子串），短语表：`退出 / 退出一下 / 退出对话 / 退出聊天 / 结束对话 / 结束聊天 / 结束会话 / 结束一下对话`；否决词 `静音 / 登录 / 登陆`。分类链中排在**音量之后**（"退出静音"先被 `volume.unmute` 接走）。
- 映射完整：`ir_route_bit`、`ir_intent_name`（"exit"）、`ir_intent_from_name` 三处同步。

执行路径说明：本层只做判定（PASS 原厂），不注册本地技能 —— `skill_dispatch.c` 的 `default: return 0` 天然回落，**该文件零改动**。

### 1.2 联动同步（全部引用 `T7B_ROUTE_ALL` 的位置逐点核查）

| 位置 | 改动 | 原因 |
|---|---|---|
| `worker_conf.c` 解析 | `exit` 名字 → `T7B_ROUTE_EXIT` 位 | 任务书 §二.7：不能只改默认值漏掉配置路径 |
| `worker_conf.c` 写回 | `wc_route_intents_str` 输出 `exit` | 写回-重载往返保位 |
| `ai_worker.c:2212` | 无改动 | 默认 `route_intents = T7B_ROUTE_ALL`，自动含新位 |
| `ai_worker.c` 启动日志 | 增加 `exit=%d` | 诊断可见性 |
| `utterance_gate.c` 快路 | `IR_EXIT → T7B_ROUTE_EXIT` | 完整退出短句走既有快路机制 |
| `libtg_hook.c:612` | `g_nlu_mask` 默认 `0x7F → 0xFF` | Hook 侧 DECIDE 登记的掩码必须含退出位 |
| `libtg_hook.c:742` | env 上限 `0x7F → 0xFF` | `TG_NLU_ROUTE_MASK` 校验与 ALL 一致 |

`ai_worker.c:2350` 的越界校验 `(~T7B_ROUTE_ALL) != 0` 引用宏本身，随 ALL 扩位自动生效，无改动。

### 1.3 超出任务书 §一"仅修改"清单的文件（如实申报）

任务书限定了 4 个文件，但完整实现必须触碰以下额外文件，均为新位的机械联动，无逻辑重构：

1. `worker_conf.c` —— 任务书 §二.7 明确要求配置路径完整（"不能只改默认值却漏掉配置路径"），与 §一清单冲突时按实现要求执行。
2. `utterance_gate.c` —— `ug_fast_ready()` 的 intent→bit switch 缺 `IR_EXIT` 分支会导致退出短句不走快路（慢路行为仍正确，但快路是该意图的既有机制）。
3. `ai_worker.c` —— 仅启动日志格式串加一列，属诊断可见性。

## 二、遗留回归的修复（需审查确认）

跑回归套件时发现一个**先于本轮**的失败：`classify("现在是什么时间") -> none`（t7_04 全量基线 141 断言中 1 失败）。

溯源：`3af077d2`（2026-11-22 09:55，"separate recognised intent from complete enough"）在 `IR_TIME_VETO` 加入了 `"是什么"`（为拦"日期格式是什么"），未同步更新 t7_04 测试 —— "现在是什么时间" 同时命中 HIT（`什么时间`）和 VETO（`是什么`），被误杀。此后每轮跑 t7_04 都带着这个失败（11-22 08:39 的 pass=141 证据日志早于该提交，之后该套件未再全量重跑过）。与退出修复无关，但任务书 §三要求"既有音量、天气、屏幕、媒体测试全部通过"，不修则回归套件带红提交。

最小修复（`ir_match_time`，6 行）：仅当句子含 `现在` 且不含 `是什么` 时豁免通用否决。验证约束全部保留：

- `现在是什么时间` → IR_TIME（修复目标）
- `我的生日是几号` / `快递几号到` → IR_NONE（否决词 `生日`/`快递` 正常生效）
- `日期格式是什么` → IR_NONE（不含 `现在`，否决不变）

**若审查认为该项应另行处理，revert `ir_match_time` 的这一个函数即可，退出修复不依赖它。**

## 三、测试结果

### 3.1 新增测试 `tests/t8_12_20_exit_route_unit_test.c`（82 断言，全 PASS）

- **[1] 正向**（任务书 §三）：`退出`、`天猫精灵退出`、`退出一下`、`结束对话` + 口语变体共 10 句 → 全部 `IR_EXIT, complete=1, rule=exit.keyword`。

  - DECIDE + 明确退出 + 路由开启 → **PASS**，`marked=0`（不登记为 AI 会话），`should_drop=0`（原厂 exitTalk 必须能执行）；

## 四、默认 mask / 旧配置兼容 / 新路由位核查清单

1. **默认 mask**：worker 默认 `route_intents = T7B_ROUTE_ALL = 0xFF`（自动含 exit）；Hook 默认 `g_nlu_mask = 0xFF`；两处与 ALL 宏一致。
2. **旧配置兼容**：旧串（如 `volume,weather,screen_off,time`）逐位等值，无 exit 位泄漏；旧设备上不含 `route_intents` 行 → 默认 0xFF 含 exit（行为变化 = 退出被放行，即本轮修复目标本身）。
3. **新位无冲突**：0x01–0x40 既有，0x80 唯一空闲高位；`~ALL` 越界校验、env 上限、写回缓冲（`o+6 < sizeof`）全部覆盖。
4. **收窄兼容**：`TG_NLU_ROUTE_MASK=0x7F` 仍合法（收窄掩码），仅默认值扩位。

## 五、已知边界（如实申报）

- **单测通过 ≠ 真机通过**：`exitTalk` 是否如反汇编预期由"退出"语音触发、DECIDE 下 type=2 合成回调的 `resnull=0`，全部待审查通过后的定向真机验证（T8-12.19 §5 序列）。
- 本轮构建产物**未推送设备**；设备上仍是 p14 hook（`5be22690…`），takeover=0。
- `ir_match_exit` 用整句精确匹配而非子串：代价是"天猫精灵帮我退出一下"这类插入语气词的变体不命中（走 AI）。这是按任务书 §二.3"不要把任意包含'退出'的长句判为退出"采取的保守取舍，宁可漏判走 AI 也不误放行。
- 测试脚本新增 `tests/run_t8_12_20_host_tests.ps1`（本轮唯一新增的非任务书文件，测试基础设施）。
