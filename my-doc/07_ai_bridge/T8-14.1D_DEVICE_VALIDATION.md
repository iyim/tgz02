## 三、A. 技能开启，真机询问"现在几点"（两轮）

### A-2 第二轮（session 1969469）+ 全程状态采样

为证明"确实进入 SPEAKING 再退出"，本轮用 350 ms 间隔采样状态文件（`evidence/t8-14.1d/poll_A2.txt`）：

```
[18:58:30] sc=IDLE/…g21/a0/t6       play=idle:…g21:ok        ← 上一轮已收尾
[18:58:54] sc=IDLE/…g22/a0/t6       play=playing:…g22:      ← TtsExec 开始播报
[18:58:57] sc=SPEAKING/…g22/a1/t9   play=idle:…g22:ok       ← 会话在 SPEAKING 且请求活动
[18:58:59] sc=FOLLOWUP/…g22/a0/t10  play=idle:…g22:ok       ← 播放结束，请求终结
[18:59:11] sc=IDLE/…g22/a0/t12      play=idle:…g22:ok       ← CLOSING→IDLE
```

采样到的状态集合：`IDLE, SPEAKING, FOLLOWUP`；`transitions` 6 → 9 → 10 → 12，`last_transition =
"CLOSING->IDLE (closed)"`。Worker 日志同一事件：`route=skill … g22` → `skill ok … reply_bytes=9`
→ `tts queued … g22`；TtsExec：`play tts_id=5246274 event=t6-30807-1969469-g22 bytes=9`；
`done/t6-30807-1969469-g22.ok`；`play.public.json` 的 `event_id` 与 `last_outcome=ok`。

## 六、状态分类（PASS / FAIL / NOT OBSERVED）

**FAIL：无。**

**NOT OBSERVED（如实标注，不做推断）**

1. **"人耳听到播报"**：我无法代替在场人员听音。可核对的是：TtsExec 以 `bytes=9`
   播报了事件文本、`play.public.json` 记录 `started_ms→finished_ms` 与 `last_outcome=ok`、
   媒体音量 25、设备 AEC 只作用于自身播放。**是否真的响**需要现场确认。
2. **队列文件的原文副本**：TtsExec 消费后把 `queue/*.json` 移入 `done/*.ok`（29 B），
   采样窗口内没有抓到 `queue/*.json` 的内容快照。技能文本长度由 `reply_bytes=9` 与
   TtsExec `bytes=9` 两处独立印证，但**"now 18:5x" 的字符串本身**本轮未留副本。
   主机侧（T8-14.1）已验证该字符串形如 `^now \d\d:\d\d$`。
3. **原厂回答的音频内容**（B 段）：只能确认放行标记已写、原厂路由接管；原厂自己 TTS 的音频不在我方观测面内。
