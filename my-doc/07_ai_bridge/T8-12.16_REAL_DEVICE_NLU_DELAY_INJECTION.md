# T8-12.16 真机 NLU 延迟注入与跨轮归属验证

- 基线：`fc23a5ed2807966513182391cefdd25e37a95bf0`
- 设备：TG-Z02 `AILABS_S1L` 192.168.1.9:5555，`:core` pid=30807 / starttime=2467080（**全程未重启**）
- 观测手段：沿用 T8-12.15 的被动探针（`libtg_hook_p15.so`，takeover 全程 0）
- 证据目录：`my-doc/07_ai_bridge/evidence/t8-12-p16/`

## 0. 结论先行

1. **任务要求的延迟条件没能构造出来**，而且我拿到了"为什么构造不出来"的硬证据：
   在这台设备上 **ASR 与 NLU 共用同一条 443 云端通路**，把网络掐住会让整轮语音直接失效
   （无 asr_final、无 NLU 回调），因此网络侧无法"只延迟 NLU 而让第二轮先登记"。
2. **但本轮意外拿到了一条真实的反序样本**：`type=3` 的回调比它自己那一轮的 ASR final
   **早 6 510 ms**，且该 sessionId 在本世代之前已被两个更早的进程世代用过，
   原厂自己在 logcat 里把这条数据当 `outdated` 清掉。
   —— 这是**不需要人为延迟就已经存在**的时序反例，直接命中 P0-1 的前提假设。
3. P0-1 仍**未关闭**；本轮把它拆成了两个可分别验证的子问题（见 §5）。

## 1. 对照实验（无任何网络干预）

PC 侧播放录音驱动两轮（间隔 250 ms 音频）：

| sid | ASR final | NLU 回调 | 延迟 | 与下一轮登记间隔 |
|---|---|---|---|---|
| 1969037 | 09:47:57.148 | 09:47:57.480 | 332 ms | **5 594 ms** |
| 1969042 | 09:48:02.742 | 09:48:03.011 | 269 ms | — |

第 1 轮回调仍领先下一轮 5 262 ms → 无跨轮归属。

> 关于审查意见第 3 条：完全同意 —— **音频间隔 ≠ ASR 轮次间隔**。实测就是 250 ms 音频间隔
> 换来 5 594 ms 的登记间隔，因为间隔由"第二段语音自身的时长"决定（该文件 5.1 s）。
> 即便换更短的第二段命令，登记间隔的下限也是那段语音的时长（约 3~4 s），仍比 NLU 延迟
> （0.27~0.47 s）大一个数量级。

## 2. 网络侧延迟注入：能力探测

| 手段 | 结果 |
|---|---|
| `tc qdisc add dev wlan0 root netem delay 200ms` | **不支持**：`Android does not support qdisc 'netem'`（toybox `tc` 不会编码 netem，`pfifo` 同样报错） |
| `iptables -w -t filter -I OUTPUT 1 -p tcp --dport 443 -j DROP` | **可用**（加 `-w` 后成功，`iptables -L` 能看到 DROP 条目） |
| 同一命令的稳定性 | **不稳定**：多次出现 `can't initialize iptables table 'filter': Permission denied`，而同一 shell 的 `CapEff=0x3fffffffff`（含 `NET_ADMIN`/`NET_RAW`）→ 不是能力问题，是 netd/xtables 竞态，**无法用于毫秒级定时** |

副作用（已修复）：一次按序号的批量删除把 netd 的 `oem_out` / `fw_OUTPUT` 跳转规则一并删掉，
已按原顺序恢复，最终 `iptables -S OUTPUT` 与动手前逐条一致（`oem_out / fw_OUTPUT / st_OUTPUT / bw_OUTPUT`，DROP 计数 0）。

## 3. 否决实验：443 全阻断 → 整轮语音失效

在 DROP 443 生效期间（`iptables -L` 已确认规则在位）播放一次完整命令：

```
events.jsonl 行数不变（无新 asr_final）
obs_total 不变（无 NLU 回调）
```

解除阻断后用同一文件重放：立即恢复（seq=80 正常出现）。

**结论：原厂 ASR 依赖该云端通路，掐断网络就没有 ASR final，也就不存在"第二轮先登记"。**
网络侧延迟无法把 NLU 与 ASR 解耦 —— 这是本设备拓扑的硬限制，不是实现细节。

## 4. 本轮意外获得的真实反序样本

```
obs i=8  mono=74737356  wall=1795399438036  sid=1969069  type=3  mode=pass  decision=PASS
ASR final seq=82  session=1969069  recv_at_ms=1795399444546
                  → 回调比它自己的 ASR final 早 6 510 ms（负延迟）
```

三条配套证据：

1. **该 sid 跨世代复用**：
   `pid 15072 → 1969069 @1795310018388`、`pid 30430 → 1969069 @1795311939183`，本世代 `pid 30807` 又出现一次。
2. **原厂自己判定它 outdated**：`AudioManager.cpp clearOutdatedData:326 remove outdated data, id:1969069, type:3`（10:04:33.806）。
3. **它是 10 条样本里唯一的 `type≠0`**（其余 9 条 type=0）。

两种解释都保留：
- (a) `type=3` 是早于 ASR final 的辅助/推送结果 → **"先登记、后结果"这个前提不成立**；
- (b) 该回调携带的是**旧世代的陈旧 id** → 跨世代误投的一例。

**P0-1 拆成两个子问题：**

- **P0-1a（常态顺序）**：type=0 的 9 条全部"final 先、NLU 后"，延迟 267~465 ms。
  要在此路径上出错，需要 NLU 延迟 > 两轮间隔（≥3~5 s）→ 常态不可能，需人为放慢 NLU。
- **P0-1b（顺序不保证）**：已经存在**回调早于本轮登记 6.5 s** 的真实样本，
  且携带的 id 属于更早世代。这条不需要构造，直接把"登记先于结果"的假设打破。

是否"错误归属"：**不能判定为是**（无法从外部看到原厂把结果投进哪个会话表项），也**不能判定为否**。
