# T8-06.2 统一修复 T6 Hook 与 NLU Stub 的页面权限处理

状态：代码 + 主机行为测试 + ARM32 编译完成，**未上真机**。

## 一、问题回顾（T8-06.1 遗留）

T8-06.1 把 `page_prot()` 的"未知"从 `7` 改成 `-1`，NLU 入口补丁路径（`nlu_pp_unprotect()`）
因此闭合了。但 T6 的三处仍按旧约定写：

| 位置 | 旧写法 | 后果 |
|---|---|---|
| `patch_entry()` | `(void)mprotect(page,4096, old ? old : (R\|X))` | 忽略返回值；`old = -1` 是真值 → `mprotect(prot=-1)` → `EINVAL` → 页面**留在 RWX**；仍返回 `TG_OK` 并 `g_patched = 1` |
| `tg_hook_uninstall()` | 同上 | 入口写回了，页面还 RWX，却 `return TG_OK`；`g_patched=0`，之后再没有机会补救 |
| `build_nlu_stub_page()` | `old = page_prot(...); if (old != 7) { mprotect(RX); mprotect(RWX); } mprotect(RX);` | 第一次 `mprotect(RX)` 返回值被丢弃；`-1 != 7` 也进分支；"RX→RWX→RX" 来回切，错误状态不可靠 |

## 二、改动（只动 `hook_agent/libtg_hook.c`）

### 2.1 新增两个 T6 页面权限助手（`entry_begin_write` / `entry_restore_prot`）

新增状态（跨"安装失败 / 卸载失败 / 重试"全程保留）：

```c
static uintptr_t    g_entry_page;              /* 入口所在页（页对齐） */
static int          g_entry_orig_prot = -1;    /* 首次确认的原始权限；-1 = 未知 */
static volatile int g_entry_prot_valid;        /* 1 = 基线已确认 */
static volatile int g_prot_dirty;              /* 1 = 恢复欠账（页面可能仍是 RWX） */
static volatile unsigned long g_entry_prot_queries, g_entry_prot_fails;
static volatile unsigned long g_entry_patch_marks, g_entry_unpatch_marks;
```

`entry_begin_write(what)`：

1. `g_func == 0` → `TG_E_SYMBOL`；
2. **只在第一次**查 `page_prot(page)`；`q < 0` 或 `q & ~(R|W|X)` → `TG_E_PROT`，
   一个字节都不写（错误文本 `cannot determine original page protection ... refusing to change protection`）；
3. 查询成功才 `g_entry_orig_prot = q; g_entry_prot_valid = 1;`；
4. `mprotect(page, 4096, RWX)`，返回值检查，失败 → `TG_E_PROT`。

`entry_restore_prot(what)`：

1. 基线未知（`!valid || orig < 0`）→ 拒绝，**绝不猜值**；
2. `mprotect(page, 4096, g_entry_orig_prot)`，失败 → `g_prot_dirty = 1` 并 `TG_E_PROT`；
3. 成功 → `g_prot_dirty = 0`；
4. **从不写 `g_entry_orig_prot`**：恢复失败后页面是 RWX，那是我们自己造成的，
   把它当成新基线等于永久放弃 W^X。

### 2.2 `patch_entry()`

顺序固定为：**确认基线与打开写权限 → 写两个字 → 记录 `g_patched` → 带检查的恢复**。

```c
rc = entry_begin_write("func entry");     if (rc != TG_OK) return rc;   /* 拒绝在前 */
p[1] = stub; flush; p[0] = TG_PATCH_JUMP; flush;
g_patched = 1;                            /* 入口真实状态，先如实记录 */
rc = entry_restore_prot("func entry");
if (rc != TG_OK) { ... "entry IS patched ... restore FAILED ... install NOT successful" ...; return rc; }
```

即：恢复失败时 `g_patched == 1`（入口确实是补丁）、`g_prot_dirty == 1`、返回 `-7`。

### 2.3 `tg_hook_uninstall()`

```
!g_patched && !g_prot_dirty              -> TG_OK（真的没事可做）
!g_patched && g_prot_dirty               -> 只重试 entry_restore_prot()；失败返回 -7，成功 TG_OK
g_patched                                -> begin_write -> 写回原厂两条 -> g_patched = 0 -> 恢复保护
                                            恢复失败: 返回 -7，g_patched 保持 0，基线保留，错误文本提示再调用一次
```

要点：**入口恢复成功 ≠ 页面保护恢复成功**；`g_patched` 只描述入口机器码，
不为了"报错好看"伪造 patched；基线不清空，供后续单独重试。

### 2.4 `tg_hook_install()`（第三节第 2 条要求，必须同时改）

幂等返回条件从 `if (g_patched)` 变成：

```c
if (g_patched && g_thread_started && !g_prot_dirty) { g_state = TG_OK; return TG_OK; }
```

随后：

```
!g_patched            -> prepare -> verify_entry_state -> build_stub_page -> patch_entry
g_patched && dirty    -> 只重试 entry_restore_prot()（不重装补丁）
然后 g_stop=0；线程在就复用，不在就 pthread_create
```

`pthread_create` 失败时的回滚也改成看返回值：回滚失败时把
`rollback of the entry patch also failed (rc=%d)` 与原因一起报出来，不再静默。

### 2.5 `build_nlu_stub_page()`

严格按映射生命周期：

1. `mmap(PROT_READ|PROT_WRITE)` —— 在该权限下填充 stub（`c[0..12]`）与 trampoline（`t[0..3]`），布局一字未改；
2. `__builtin___clear_cache` 刷新整页；
3. `mprotect(RX) == 0` → 成功，`g_nlu_page_prot = R|X`、`g_nlu_page_degraded = 0`；
4. 否则记 `rx_errno`，`mprotect(RWX) == 0` → 成功但**记降级**（`degraded = 1`，`slog` 写明 RX 失败原因）；
5. 两者都失败 → `nlu_err_set("... RX errno=%d, RWX errno=%d; stub page released ...")`，
   `munmap` + `g_nlu_page = NULL` + `*err_out = TG_E_PROT`，**不假装可执行**。

删除了 `page_prot()` 查询与"先 RX 再 RWX 最后 RX"的来回切换：
`mmap` 出来就是 RW，不需要先查、也不需要先降。

### 3.1 做法

`tests/run_t8_062_host_tests.ps1` 从 `libtg_hook.c` **逐字抽取** 8 个函数

`(addr,len,prot)` 序列，可按 RWX / 恢复位分别失败，也可"第 N 次恢复才失败"）、
`mmap/munmap`、`pthread_*`（记录，不起真线程）、`sender_main`、`tg_hook_prepare`、

## 四、ARM32 构建

`build_t6.ps1 -LogName t8_062_ndk_build.log`：0 warning / 0 error，ELF32 / ARM。
`tg_injector` 依赖未变（本轮未动）；`libtg_hook.so` 见日志 sha256。

反汇编抽查（`evidence/t8_062_disasm_check.txt`）：

- `entry_begin_write` 独立成函数（`0x38b0`）：`bfc r4,#0,#12` 页对齐 →
  `bl page_prot` → `cmp r0,#8 / bcc` 即"未知或非法位一律拒绝" →
  `str valid=1` / `str orig` → `mov r2,#7; bl mprotect; cmp r0,#0`；
  两个错误出口是 `mvn r0,#2`（-3）与 `mvn r0,#6`（-7）。
- `tg_hook_uninstall` 里两次 `bl mprotect`，第二次的 `r2` 来自全局
  `g_entry_orig_prot`（`ldr r2,[pc,#736]; ldr r2,[pc,r2]`），不是常量 5 或 7。
- `patch_entry` / `entry_restore_prot` 在 `-O2` 下被内联（无独立符号），
  逻辑体现在 `tg_hook_install` / `tg_hook_uninstall` 的调用序列里。

## 五、仍未消除的风险

1. **RWX 窗口本身**：`mprotect(RWX)` 到恢复之间，其他线程可以写入口页。
   本轮的改动只是"失败不再被吞"，窗口依旧存在（真要消除得用
   `mprotect(RX)` + `/proc/self/mem` 写入或 `pkey`，Android 8.1 上都不朴素）。
2. **基线只读一次**：若之后有别的组件改了这一页的权限，我们仍按旧基线恢复，
   不会发现。T6 侧目前没有像 NLU 那样的 `tg_nlu_prot_state()` / `tg_nlu_prot_restore()`
   手动查询入口，只有 `g_entry_prot_queries` / `g_entry_prot_fails` 计数可读。
3. **首次写时页面已经是可写**（上一轮遗留 RWX 且基线从未确立，例如进程刚启动就被
   外部改成 RW）：基线会记成 `7` 并"如实恢复成 7"。`g_prot_dirty` 之后不会再报，
   只能靠人工 `tg_hook_uninstall()`（有欠账时才动）或重启进程。
4. **入口写回与恢复仍非原子**：`p[0]`/`p[1]` 写回原厂序言的两条 `str` 之间若线程
   正在 `func+4` 执行，仍有一个 `~ns` 级窗口（与安装方向对称，T6 原有特性）。
5. **`build_stub_page()`（T6 的 stub 页，不是 NLU 的）未改**：它是 `mmap(RW)` →
   填充 → `mprotect(RX)`，失败退 RWX，两条路径都检查了返回值，因此不属于本轮 P1；
   但它同样不记录"是否降级成 RWX"（NLU 侧本轮已记录）。
6. **真机行为未验证**：全部结论来自主机行为测试 + ARM32 编译；内核 `mprotect`
   实际返回值、SELinux permissive 下的 `execmod` 行为仍需真机阶段确认。
