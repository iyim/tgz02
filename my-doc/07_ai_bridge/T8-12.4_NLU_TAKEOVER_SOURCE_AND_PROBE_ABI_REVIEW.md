## 〇、结论摘要（含对第三阶段的一处自我推翻）

1. **`what=11` 不是"跨 sid + TTS 流式"专属路径。第三阶段的这句话必须撤销。**
   静态链路给出了**两个独立触发源**，其中第二个**没有任何 sid 或 TTS 前置条件**：

   ```
   触发源 A（有门控）
     SessionManager::onNlpResult(0x11489c)  D 路
       sid != this->[64]  且  ProtocolData::isTtsStreaming(res) 为真
       -> SessionProxy::onNlpResultInner(sid,res) -> Message::obtain(what=11)

   触发源 B（无门控，本次新发现）
     GcsManager::onResult(0x12febc)              ← 网络/GCS 回包回调
       -> RouterManager::onResponse(0x10fe3c)    ← 全库唯一调用点 0x12ff9c
            -> ProtocolParser::onParser -> new NlpResult(152B)，写 [+140] = sid
            -> (id>>20)&0xF ∈ {3,5} 时
       -> SessionManager::onNlpResultInner(0x114b98)   ← 无 sid 比较、无 isTtsStreaming
            -> SessionProxy::onNlpResultInner -> obtain(what=11)
                 -> 分发器 what=11 -> SessionDispatch::onNlpResultInner(0x11896c)
                      -> playAudios(0x20000, sid, res, ...)     ← **绕过 onNlpResult 补丁**
   ```

2. **R16 因此从"跨 sid 边界情形"升级为"云侧结果主通路完全不受补丁约束"（P0）。**
   这同时意味着：第三阶段"同 sid 常规结果不可能走 what=11，所以补丁覆盖主路径"的推论**只在触发源 A 的前提下成立**，不能推广。

3. **探针 ABI 已经落地成可编译、可执行的 68 字节桩，并在主机侧 ARM32 模拟中通过 22 条断言**：
   参数落位（r0/r1/r2/r3 + `[sp]`/`[sp+4]`）、回调故意写入垃圾后 r0-r3/r12/lr 全部复原、回调入口 SP 8 字节对齐、返回后 SP 复原、重放真实 `playAudios` 序言后 `r11-sp=28`、连续 1000 次调用 SP 无漂移。
   **但真机/真实硬件未执行**，且"回调内部禁止事项"只是约定，未做运行时防护。

4. **安装/回滚可以与安装点一一对应**：6 个入口的前 8 字节全部是寄存器类指令（`push` / `add r11,sp,#N`），不含 PC 相对寻址，因此 8 字节补丁 + 2 条指令重放对所有入口都成立；并发安全不是靠"单 Injector 锁"，而是靠**现有 `pause_and_check()`（ptrace 暂停全部线程 + PC 区间核对 + 12 次重试）**。

5. **仍有一项关键观测在"不改生产 Hook"的前提下不可观测**：`tg_nlp_cb` 是否被调用（R19）。本阶段按评审要求把它标为**不可观测**，并重写了 U1 判据，不用间接证据冒充。

6. **生产实现仍然不可以进入**，但阻塞点已从"来源不清"转移为"云侧路径未被覆盖 + 收尾分类未定"。

## 三、任务 B：探针 ARM32 ABI

### 3.1 采用的约定

- **AAPCS（AAPCS32 / ARM EABI）**，ARM 态（`UC_MODE_ARM` / 被测函数入口均为 ARM 指令）；
- 回调原型：

  ```c
  void tg_probe_cb(uint32_t site, uint32_t a0, uint32_t a1,
                   uint32_t a2, uint32_t a3, uint32_t caller_lr);
  ```

- 参数落位：`r0=site`、`r1=a0`、`r2=a1`、`r3=a2`、**`[sp+0]=a3`**、**`[sp+4]=caller_lr`**；
- 栈必须 **8 字节对齐**（AAPCS 对公共接口的要求，VFP 使用前提下强制）。

### 3.2 完整汇编（`probe_abi/probe_stub.S`，已编译）

```asm
        .arm
        .syntax unified
tg_probe_stub:
        push    {r0, r1, r2, r3, r12, lr}   @ +0x00  24 B
        sub     sp, sp, #8                  @ +0x04  参数区
        mov     r0, #SITE_ID                @ +0x08  第 1 参
        ldr     r1, [sp, #8]                @ +0x0c  第 2 参 = 保存的 r0
        ldr     r2, [sp, #12]               @ +0x10  第 3 参 = 保存的 r1
        ldr     r3, [sp, #16]               @ +0x14  第 4 参 = 保存的 r2
        ldr     r12, [sp, #20]              @ +0x18  取保存的 r3
        str     r12, [sp, #0]               @ +0x1c  第 5 参 = [sp+0]
```

### 3.3 参数落位与栈布局（逐格推算）

| 时刻 | SP | 说明 |
|---|---|---|
| 进入桩 | `S` | 被观测函数的入口 SP（8 字节对齐） |
| `push {r0..r3,r12,lr}` | `S-24` | `S-24` 仍是 8 的倍数 |
| `sub sp,#8` | `S-32` | 调回调时的 SP，8 字节对齐 ✔ |

栈内容（`sub` 之后）：

| 地址 | 内容 |
|---|---|
| `sp+0` | a3（第 5 个参数） |
| `sp+4` | caller_lr（第 6 个参数） |
| `sp+8` | 保存的 r0 |
| `sp+12` | 保存的 r1 |
| `sp+16` | 保存的 r2 |
| `sp+20` | 保存的 r3 |
| `sp+24` | 保存的 r12 |
| `sp+28` | 保存的 lr = **被观测函数被调用时**的返回地址 |

`caller_lr` 就是"调用点地址 + 4"（ARM `bl` 的返回地址），因此它可以把"哪个 `bl` 调进来"钉死到指令级：例如 `what=11` 分支的 `0x11c41c` 调用会在回调里看到 `caller_lr = 0x11c420`。

### 3.4 寄存器保存与恢复策略

| 寄存器 | 处理 | 依据 |
|---|---|---|
| `r0-r3` | 入口 `push`、出口 `pop` | 回调是 C 函数，可任意破坏易失寄存器；桩必须复原，否则被观测函数拿到的是垃圾 |
| `r12` | 同上 | 桩只用 r12 作临时寄存器 |
| `lr` | 同上 | trampoline 需要原始返回地址 |
| `r4-r11` | **完全不碰** | AAPCS 规定 callee-saved；桩不写它们，也就无需保存 |
| `sp` | `push 24` + `sub 8` / `add 8` + `pop 24` | 成对，净变化 0 |
| `CPSR` | **不保存** | AAPCS：条件标志在函数调用边界是**未定义/易失**的，调用者不得依赖跨调用的标志。各安装点入口前 3 条指令（`push`/`add`/`sub`）都不读标志 → 不保存是安全的（见 §四.1 的字节表） |
| GE/IT 等扩展状态 | 不使用、不修改 | 桩全程 ARM 态、无条件执行、无 IT 块 |

### 3.5 trampoline 与 ARM/Thumb、PC 相对寻址

- trampoline 结构（每个安装点一份，16 字节）：
  `[原第 1 条] [原第 2 条] [E51FF004 ldr pc,[pc,#-4]] [func+8]`；
- 执行时 **SP == 入口 SP**（桩已经 `pop` 复原），所以被搬运的两条 prologue 指令（`push` / `add r11,sp,#N`）语义完全不变；
- 桩与 trampoline 全部位于**匿名可执行页**（`mmap`），与目标函数不在同一段，因此不存在"页内相对偏移被破坏"的问题；
- **ARM/Thumb**：6 个安装点的入口都是 ARM 指令（`push {…}` 为 4 字节 ARM 编码），`func+8` 的最低位为 0 → `ldr pc,[…]` 不带状态切换，天然保持 ARM 态；若将来要 hook Thumb 函数，必须改用 `ldr pc` + `addr|1`，本方案不覆盖（记为限制）；
- **PC 相对寻址**：只有当被覆盖的指令本身是 `ldr rX,[pc,#imm]`、`adr`、`b`/`bl` 或字面量池时才需要重定位。本阶段逐条核对了 6 个入口的前 8 字节，**没有任何一条属于这一类**（§四.1），所以"直接复制 2 条指令"是安全的。

### 3.6 回调内部禁止事项（约定 + 可验证依据）

| 禁止 | 理由 | 如何验证 |
|---|---|---|
| 调用任何被观测库内的函数 | 会重入分发器/分配器，破坏被观测函数的前提 | 探针源码里不允许出现对目标库符号的 `dlsym` |
| 取锁、`malloc`、文件/网络 I/O | 回调运行在被观测函数入口，任何阻塞都会改变原厂时序 | 代码审查 + 环形缓冲在 `mmap` 时一次分配 |
| 修改入参或 `Message`/`NlpResult` | 会改变原厂行为 | 回调参数按值传递（`uint32_t`），无指针解引用写 |
| 递归打点 | 同一线程重入 | `site` 固定 + 环形缓冲单生产者；同线程重入会体现在 `seq` 连续但 `site` 相同，属于可识别现象 |
| 长时间执行 | 影响实时性 | 单条 `PROBE=` 格式化的固定上界（≤ 数个 `snprintf`） |

以上均为**约定**，本阶段没有做运行期防护（如栈金丝雀、时限检测）。

对每一个入口：

- **覆盖字节数**：8（两条指令）；
- **补丁后**：`0xE51FF004`（`ldr pc,[pc,#-4]`）+ `<stub 地址>`；
- **trampoline**：`[原 1] [原 2] E51FF004 <func+8>`；
- **安装前检查**：该 8 字节必须**逐字等于**上表的 `[vaddr+0]/[vaddr+4]`（不是就不用，直接失败退出）；
- **卸载后检查**：读回 8 字节必须逐字等于同两张表项；
- **PC 相对指令**：六个入口的前 8 字节**均无**（这是本方案成立的前提）。

### 4.2 运行期地址计算

```
base = dli_fbase from dladdr(dlsym(RTLD_DEFAULT, "任一导出符号"))
addr(entry) = base + (vaddr - <该符号的 vaddr>)
```

**不得**使用"libsmartbox 基址 + vaddr"的硬编码（§2.6 的双副本问题）。若 `dlsym` 返回的地址与"libsmartbox 基址 + vaddr"不一致，说明赢家是另一份实现，此时必须按赢家的映射重新推导，且**六条入口必须来自同一份实现**（同一次 `dladdr` 结果），不允许混合。

### 4.3 并发安全：不能靠"单 Injector 锁"

评审意见成立：`--on/--off` 的互斥只解决"两个安装器互相踩"，**不解决目标线程正在执行那 8 字节**。本项目的现有实现已经解决了这个问题，可直接复用：

【源码】`android/injector/tg_injector.c:184-226`：

```c
static int pause_and_check(uint32_t lo, uint32_t hi, char *err, size_t errlen)
{
    const int max_attempts = 12;
    for (attempt = 1; attempt <= max_attempts; attempt++) {
        int rc = rc_pause_all(&g_ctx, &g_paused, err, errlen);   /* ptrace 逐个 attach 全部线程 */
        ...
        rc = rc_pc_in_range(&g_ctx, &g_paused, lo, hi, &offender, err, errlen);
        if (rc == 0) return RC_OK;          /* 所有线程已停且区间干净 */
        rc_resume_all(&g_paused);           /* 有线程的 PC 落在区间内：放回、等 20ms、重试 */
        usleep(20000);
    }
    return RC_E_UNSAFE;
}
```

`rc_pause_all()` 还会**重新枚举 tid 最多 8 轮**，以覆盖"暂停过程中新线程被创建"的竞态。

因此本阶段的判定是：

> **并发安全有可实施路径**：`pause_and_check(entry, entry+8)` + `world_frozen=1` 传入补丁事务；安装/卸载都必须走这条路径（从进程外用 ptrace 触发），**不允许在进程内自行写入口**。

### 4.4 更安全的替代：单字 `b` 补丁

`ldr pc,[pc,#-4]` + 地址 = 8 字节 = 两次 32 位写，**不是原子的**：若某线程正好在两次写之间取指，会执行到"新第 1 条 + 旧第 2 条"的半条指令（`ldr pc,[pc,#-4]` 会把旧第 2 条的编码当地址跳过去）。这正是 `pause_and_check()` 要规避的窗口。

替代方案（推荐用于探针）：

- 只写**一个字**：`b <stub>`（`0xEA??????`，±32 MB），ARM 对齐单字存储是**原子**的；
- 代价：stub 必须落在目标函数 ±32 MB 内 → `mmap` 时给 hint（目标地址附近），失败则回退到 8 字节方案；
- trampoline 只需重放**1 条**指令并跳回 `func+4`；
- 卸载 = 单字写回原第 1 条，同样原子；
- **仍然不能立即 `munmap` stub 页**：可能已有线程刚刚取到 `b` 并正在进入 stub。安全做法是保持映射（泄漏 1 页）或延迟回收（本阶段不做自动回收）。

### 4.5 如何证明"所有入口都恢复了"，而不是只验一部分

1. 探针维护 `installed_mask`（每个 site 一个 bit），安装/卸载都更新并打印；
2. `--verify` 模式：对**表中全部 6 个**入口逐个读回 8 字节并与记录的原值比较，输出 `verify site=<id> addr=0x… ok|MISMATCH`，最后输出 `verify_total=ok/6`；
3. 只要有一个 `MISMATCH` 或 `installed_mask != 0`，退出码非 0，并在 `maps` 核对前就判定"未完全回滚"；
4. 额外核对：`/proc/<pid>/maps` 中不含探针 stub 页；`/proc/<pid>/task/*/stat` 中无 `t`（tracing stop）状态的残留线程（ptrace detach 是否彻底）。

### 4.6 失败处理

| 失败 | 处理 |
|---|---|
| 安装时入口字节不匹配 | **不写**，报 `E_ENTRY_MISMATCH`（可能被别人 patch 过，或赢家是另一份实现） |
| `pause_and_check` 12 次仍不干净 | **不写**，报 `E_UNSAFE`（沿用现有 `RC_E_UNSAFE`） |
| 写后读回不一致 | 立刻用原字节尝试回写一次；仍不一致 → 报 `E_VERIFY`、置 `installed_mask` 对应位、**停止后续安装** |
| 卸载时读回不一致 | 报 `E_RESTORE`，不重试覆盖、不重启进程，保留现场 |
| stub 页 `munmap` 失败 | 记录 `errno`；入口已恢复即可，页面作为孤儿记录在案 |
| 任一入口恢复失败 | 整体判"未完全回滚"，禁止继续采集，也禁止重启 `:core` |

### 4.7 判定

| 问题 | 判定 |
|---|---|
| 6 个安装点能否与回滚清单一一对应 | **能**（§4.1 的表就是清单） |
| 并发安装/卸载是否安全 | **有条件安全**：必须走 `pause_and_check` + `world_frozen`；单字 `b` 方案可进一步降风险 |
| 是否具备"可实施"资格 | **是**（工程前置见 §八） |
| 是否现在就能执行 | **否**（本阶段禁止真机，且 §八 三项前置未完成） |

## 八、结论

### 8.1 `what=11` 来源判断是否可靠

| 问题 | 答案 |
|---|---|
| 是否真的"只能由 sid 不匹配 + isTtsStreaming 触发" | **否**。存在触发源 B（GCS 回包 → `onResponse` → `onNlpResultInner`），无任何前置条件 |
| 触发源集合是否已经闭合 | **库内闭合**：`what=11` 的生产者只有 1 个 `obtain` 调用点，其上游 2 条路径已全部展开到 `GcsManager::onResult` / `SessionManager::onNlpResult` |
| 是否存在库外调用者 | **静态否定**：823 个 `.so` 中无任何 `UND` 导入；仅 `dlopen`+`dlsym` 不能排除（U11） |
| 是否影响接管设计 | **是**：`playAudios(0x20000)` 这条执行链完全不受 `onNlpResult` 补丁约束 |

### 8.2 探针是否可靠

| 项 | 状态 |
|---|---|
| 参数传递符合 AAPCS | **已验证**（模拟执行，22 条断言） |
| `caller_lr` 正确 | **已验证**（等于调用点 + 4） |
| 回调前后 SP 一致、非易失寄存器不变 | **已验证**（含 1000 次无漂移） |
| 原始函数返回值/行为不变 | **已验证**（合成用例 + 真实 `playAudios` 序言） |
| 真机/真实硬件 | **未验证** |
| 回调内部禁止事项的运行期防护 | **未实现** |

### 8.3 安装与回滚是否可验证

**可以，条件是**：① 走 `pause_and_check` + `world_frozen`（不是"单 Injector 锁"）；② 六个入口按 §4.1 的表逐项读回校验并汇总 `verify_total`；③ 补丁地址从 `dlsym` 反算（R21）。

### 8.4 距离生产实现还差什么

1. **R16 必须先有处置决定**：云侧 `what=11` 路径是否也纳入接管（补齐 `onNlpResultInner`/`onPushNlpResult`），还是明确"只管本地/语音引擎结果"。这决定 T8 的目标边界。
2. **R13 的 `type` 分类必须先定策略**（`type=3` 永不丢，`type=2` 默认不丢）。
3. **R19 必须接受"不可观测"**，或单独立项给 `tg_nlp_cb` 加只读计数。
4. **U10 必须先定**（哪一份副本在跑），否则补丁地址表可能整体作废。

### 8.5 需要决策的事项

| # | 决策点 | 选项 |
|---|---|---|
| D1 | 是否接受"`what=11` 有两个触发源、R16 是云侧主通路"的重新定级 | A：接受（推荐）／B：要求进一步证明触发源 B 在真机上确实发生 |
| D2 | 接管边界 | A：只管 `onNlpResult`（保持现状，放弃云侧结果接管）／B：同时接管 `onNlpResultInner`+`onPushNlpResult`（补丁点从 1 变 3）／C：先只观测，边界后定 |
| D3 | 探针补丁形态 | A：单字 `b`（原子，推荐）／B：8 字节 `ldr pc`（与生产一致，必须 world-frozen） |
| D4 | `tg_nlp_cb` 命中是否可观测 | A：接受"不可观测"（推荐，本轮不碰生产 Hook）／B：批准给 `NLS_PASS` 分支加只读计数器（属修改生产 Hook） |
| D5 | 是否批准探针进入下一阶段构建（仍需真机授权） | A：批准构建与主机侧演练（不含真机）／B：继续静态 |
