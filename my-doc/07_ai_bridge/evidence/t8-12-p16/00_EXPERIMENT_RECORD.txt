二、网络侧延迟注入：先做能力探测
------------------------------------------------------------
1) tc netem 不可用：
   tc qdisc add dev wlan0 root netem delay 200ms
   → "Android does not support qdisc 'netem'"（toybox tc 不支持 netem 编码；
     同一二进制对 pfifo 也报 "does not support qdisc"；netem 需要独立 iproute2 的 tc）
2) iptables 可用，但在 netd 管理下不稳定：
   - 成功：`iptables -w -t filter -I OUTPUT 1 -p tcp --dport 443 -j DROP`
     （用 -w 后成功，`iptables -L OUTPUT -n` 可见 DROP 条目）
   - 失败：多次出现 "can't initialize iptables table `filter': Permission denied"，
     而同一 shell 的 CapEff=0x3fffffffff（含 NET_ADMIN/NET_RAW），
     说明不是能力问题，是 netd/xtables 竞态 → 规则操作不可用于精确定时。
   - 副作用（已修复）：一次 `-D OUTPUT 1` 的批量删除把 netd 的 oem_out/fw_OUTPUT
     跳转规则一起删掉了；已按原顺序恢复，最终校验：
       -P OUTPUT ACCEPT
       -A OUTPUT -j oem_out
       -A OUTPUT -j fw_OUTPUT
       -A OUTPUT -j st_OUTPUT
       -A OUTPUT -j bw_OUTPUT
     DROP 条目计数 0。

三、关键否决实验：443 全阻断后，整轮语音直接失效
------------------------------------------------------------
在 DROP 443 生效期间（已用 iptables -L 确认规则在位）播放一次完整命令：
  events.jsonl 行数不变（无新 asr_final）、obs_total 不变（无 NLU 回调）。
解除阻断后同一文件重放：立刻恢复（seq=80 正常出现）。
⇒ **原厂 ASR 与 NLU 共用同一条 443 云端通路**：把网络掐住，ASR final 根本不产生，
  也就无从"延迟 NLU 而让第二轮先登记"。网络侧无法把 NLU 与 ASR 分离。

四、本轮仍然拿到了一条真实的异常样本（非构造）
------------------------------------------------------------
观测环里第 9 条（i=8）：
  obs i=8 mono=74737356 wall=1795399438036 sid=1969069 type=3 mode=pass decision=PASS
对应同一世代该 sid 的 ASR final：
  seq=82  session=1969069  recv_at_ms=1795399444546   （10:04:04.546）
⇒ 回调发生在 ASR final **之前 6 510 ms**（负延迟）。

三条配套证据：
1. 该 sid 在本世代之前**已被两个更早的进程世代用过**：
     pid 15072  session=1969069  1795310018388  "天猫精灵"
     pid 30430  session=1969069  1795311939183  "天猫精灵音量调到百分之十"
   → sessionId 跨世代复用（与 T8-12.14 的 42/568 复用统计一致）。
2. logcat（10:04:33.806）原厂自己在清过期数据：
     AudioManager.cpp clearOutdatedData:326 remove outdated data, id:1969069, type:3
   → 原厂把"id=1969069、type=3"当作 outdated 处理。
3. 这是本轮 10 条记录里**唯一 type≠0** 的一条（其余 9 条全 type=0）。

两种可能，都必须保留：
  (a) type=3 是"早于 ASR final 的辅助/推送结果" → **顺序不保证**，注册晚于结果；
  (b) 该回调携带的是**旧世代的陈旧 id**（跨世代误投）→ 跨轮归属的真实一例。
无论哪一种，都说明"先登记、后结果"这个前提在原厂时序里并不成立。

六、是否发生"错误归属"
------------------------------------------------------------
