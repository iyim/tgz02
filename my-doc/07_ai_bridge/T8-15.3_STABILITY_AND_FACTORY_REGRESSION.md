# T8-15.3 连续对话稳定性与原厂功能回归

**基线**：`bb165e52`（T8-15.2）
**结论**：连续对话主链路未退化（一次唤醒 → 5 轮无唤醒 → 语音退出 → 再唤醒，真机复测通过），补上了三道防重复开麦的闸门、修好了会话统计口径，并完成原厂音量/静音/媒体/退出/再唤醒的真机回归。

---

## 1. 防重复开麦与打断（本轮实现，真机验证）

T8-15.2 的自动续听只有一个条件（我方 TTS 播完）。本轮加了三个独立闸门，全部在 native 守卫里，不改原厂任何逻辑：

| 闸门 | 依据 | 作用 |
|---|---|---|
| 原厂会话标记 | hook `AGSpeechEngineProxy::startTalk`（libsmartbox `0xe90a8`，序言 `E92D4BF0/E28DB018` 校验）置 `listening=1`；hook `SessionManager::onStopTalk`（`0x113918`）在 EOU 置 `listening=0` | 原厂已经开着麦就绝不再开 |
| 去抖 | 距上次续听 < 800 ms 不开 | 防止 TTS 状态文件抖动导致连开 |
| 停止/退出优先 | worker 判定 `intent=exit/stop` 时写 `<state>/listen_hold`（CLOCK_MONOTONIC 绝对到期时间，退出 60 s / 停止 20 s）；守卫读到未过期就跳过 | 用户说"退出"之后不再自动开麦 |

**真机证明（停止优先）**：手工写入一个 3 分钟后到期的 hold，然后正常唤醒提问：

```
22:10:45  wake + 现在几点 → 我方回答播完
22:10:46  tgt: continuity: hold active for 172383 ms more - auto-listen skipped
22:10:46  tgt: continuity: auto trigger skipped (stop/exit hold) finished_ms=1795443046239
```

没有续听会话产生；清掉 hold 后下一轮立刻恢复正常。`evidence/t8-15.3/` 里另附正常五轮的对照。

**插话实测（播报期间说话）**：`evidence/t8-15.3/interrupt_during_playback.logcat`

- 22:09:47 唤醒 + "现在几点"，回答开始播放；
- 22:09:52 在播报中播第二句"给我讲个笑话"；
- 播报期间原厂**没有**开新会话（不失焦、不抢麦）；我方回答播完后自动续听开了一次麦（`n=6`），**只截到句尾"笑话"**。

⇒ 结论要写清楚：**播报期间的插话不会被采集**（原厂麦克风此时是关的），漏进下一轮的是句尾残片，会造成半句识别。这是当前行为，不是"打断已支持"。后续要处理的话，正确做法是给"新开麦后 X ms 内到达的短 final"加丢弃策略，但这会误伤"退出/静音"这类短指令，需要产品口径，本轮不做。

## 2. 会话统计口径修复（真机复测）

问题现象（T8-15.2 报告里被审查指出）：`rounds_done=6`、`followup_rounds=21`、同一轮三条 `factory stop talk`。

根因三条，逐条修掉：

| 现象 | 根因 | 修法 |
|---|---|---|
| 一轮三条 `talk_stops` | 原厂同一轮 EOU 连打 `onStopTalk` / `onListenStopped` / `reason=-1` | 只在"聆听 → 停止"状态跃迁上计数 |
| `exit_talks` 虚高 | `exitTalk` 一条会话里重复打印 | 200 ms 去重窗口 |
| `rounds_done` 多 1 | 退出语被当成一轮对话 | `sc_note_exit_turn()`：判定 exit 时把 `round` 和 `followup_rounds` 一起退回，并单记 `exit_turns` |
| `followup_rounds` 累计值混进单轮日志 | 该字段是进程级累计，日志里却按"本段对话"打印；同时新对话分支没有归零 | 新对话一律归零，另加 `followup_rounds_total` 记累计；日志两个都打 |
| 连续对话跑够 12 次后永久安静 | `continuity_auto_max` 是进程级上限 | 改为"每段对话"上限：距上次续听 >30 s 视为新对话，计数归零 |

**真机复测（修后）**：

```
22:15:25 dialog end by voice: intent=exit (rounds_done=5 followup_rounds=4 followup_total=5 exit_turns=1)
```

5 轮对话、其中 4 轮是免唤醒续听、退出语单独计一次、不再污染轮次 —— 与真机实际发生的事一一对应。

## 3. 原厂基础功能真机回归

用 T7-05 时代同一批 wav 在真机播放（PC 扬声器 → 设备麦克风），守卫与自动续听全程开启：

| 指令 | 识别结果 | 路由 | 执行证据（真机日志） |
|---|---|---|---|
| 天猫精灵音量调大一点 | ✅ | `route=native intent=volume rule=volume.up` | `volume_level_ is 20` → **30**（22:07:02） |
| 天猫精灵音量调小一点 | ✅ | `route=native` | **30 → 20**（22:09:14） |
| 天猫精灵静音 | ✅ | `rule=volume.mute` | **30 → 0**（22:07:26） |
| 天猫精灵取消静音 | ✅ | `rule=volume.unmute` | **0 → 30**（22:07:44） |
| 天猫精灵播放音乐 | ✅ | 原厂媒体 | `MediaPlayer.cpp:484 setDataSource` + `MEDIA_PREPARED`（22:08:54） |
| 天猫精灵暂停 | ✅ | `intent=stop rule=stop.keyword` | worker 下发 `tts stop requested`，原厂停播 |
| 天猫精灵退出 | ✅ | `intent=exit` | 平台 `exitTalk` + worker 关闭对话 + hold 生效 |
| 退出后重新唤醒 | ✅ | KWS | 新会话 `wakeupType=0`，`round=0` 全新对话 |

证据文件：`evidence/t8-15.3/factory_volume_mute.logcat`、`factory_volume_down_media.logcat`。

未覆盖项（如实记录）：`继续播放`（媒体恢复）在无媒体播放时识别到了，但没有可恢复的播放源，**未能证明恢复行为**；本轮未做"连续对话中同时下原厂指令"的组合场景（单指令与续听交替已在上面覆盖）。

## 6. 仍未解决（下一阶段）

1. **播报期间插话只截到句尾**（见 §1），需要产品定义再决定过滤策略。
2. **`继续播放` 的媒体恢复未验证**（无播放源）。
3. **连续对话中即时打断（barge-in）没有实现**：现在必须等播报结束才开麦。真 barge-in 需要原厂 AEC + 播放期开麦，超出"不替换原厂链路"的边界，需要单独评估。
4. 我方续听会话 `onListenStarted,696` 尾部三字段仍与原厂不同（`0,0,0` vs `0,1,-1`），含义未查清，实测不影响识别。
