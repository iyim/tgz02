# TG-Z02 产品 UI 架构（T9-UI-01）

> 本文是 TG-Z02 的界面骨架，后续所有页面开发（T9-UI-02、T10 技能中心、闹钟/日程/音乐）
> 都以本文为约束基线。改动架构必须先改本文，再改代码。
>
> 配套文档：`UI_DESIGN_SYSTEM.md`（视觉与组件）、`UI_SKILL_EXTENSION.md`（技能扩展契约）、
> `UI_IMPLEMENTATION_MAP.md`（落到现有技术栈的方式）。可执行原型：`prototype/`。

---

## 1. 产品定位

**以语音 AI 为核心、靠技能不断扩展能力的桌面智能助手。**

不是聊天 App，也不是语音调试面板。三条推论决定了整个界面：

| 推论 | 界面后果 |
| --- | --- |
| 用户不"操作"，而是"说话" | 首页是一个状态显示区，不是输入区；没有文字输入框、没有发送按钮、没有会话列表 |
| 界面的主要信息是"我现在在做什么" | 首页第一屏必须能回答：待唤醒 / 在听 / 在想 / 在说 / 被打断 / 出错 |
| 能力会一直增加 | 新能力只能从技能中心进来，导航结构一次定死，不再为每个新功能改导航 |

## 2. 一级导航（固定五项，不再增加）

| 页面 | 唯一职责 | 不放什么 |
| --- | --- | --- |
| **首页** | 语音交互与其运行状态、常用技能快捷入口 | 任何配置项、任何历史列表、任何文字输入 |
| **技能中心** | 技能发现、启用、停用、进入技能页面 | 配置项（属于设置）、记忆内容 |
| **记忆中心** | 长期记忆的查看、分类、编辑、删除、启停、待确认 | 模型配置、对话记录 |
| **设置** | 大模型、语音、外观、系统的配置 | 记忆内容、技能功能页 |
| **关于** | 版本、运行状态、诊断、许可 | 任何会改变行为的开关 |

一句话边界：**首页负责交互，技能中心负责能力，记忆中心负责长期数据，设置负责配置，关于负责诊断。**
四者的内容不允许互相穿插——这是本设计里最硬的一条规则。

### 导航形态

左侧固定导航栏 + 中央内容区 + 可选底部操作条。

```
+--------+--------------------------------------------------+
| 208dp  |  header 56dp（标题 / 面包屑 + 页面动作）           |
| 导航   +--------------------------------------------------+
| 栏     |                                                  |
|        |  body（24dp 页边距，14dp 纵向间距）                 |
|        |                                                  |
| 状态   +--------------------------------------------------+
| 区     |  footer（仅当本页有主操作时出现，56dp）             |
+--------+--------------------------------------------------+
```

- 导航栏 208dp；窗口宽度不足 900dp 时收成 72dp 图标条（不隐藏、不改成抽屉）。
- 二级页面**不新增导航项**：用 header 左侧面包屑 `技能中心 / 闹钟` 表达层级，
  返回只回上一级，绝不跳回首页。
- 唯一例外：进入某个技能后，导航栏在「技能中心」下方展开该技能的二级菜单
  （闹钟 / 日程 / 音乐 / 全部技能），让用户能看到同级技能并直接切换。

## 3. 页面树

```
首页 ──────────────── (唯一交互页，9 个语音状态)
技能中心
 ├── 技能详情/功能页 × N      ← 统一 5 区结构，见 UI_SKILL_EXTENSION.md
 │    ├── 闹钟
 │    ├── 日程
 │    ├── 音乐（未接入）
 │    └── …（天气 / 设备控制 / 未来技能）
 └── 技能管理（启用 / 停用 / 排序）
记忆中心
 ├── 记忆详情（编辑）
 └── 待确认队列
设置
 ├── 大模型配置 ── 配置编辑对话框
 ├── 语音
 ├── 外观
 ├── 系统
 │    ├── 对话记录（只读历史，维护用）
 │    └── 诊断导出
 └── 清除数据
关于
 ├── 更新日志
 └── 开源与许可
```

### 职责迁移（相对当前已上线的 T9-07/T9-08B 界面）

| 现状 | 目标 | 处理方式 |
| --- | --- | --- |
| 首页右上「设置 / 更多」两个文字按钮 | 设置进导航栏；「更多」取消 | 一级导航替代按钮 |
| `MoreActivity`（文字对话入口） | 取消 | 文字输入不再出现在任何页面 |
| `ConversationActivity`（文字输入 + 会话 + 历史） | 迁移为 **设置 → 系统 → 对话记录**（只读 + 清空） | 保留代码能力，去掉入口与输入框；调试输入继续用 adb 脚本 |
| `SettingsActivity`（一页长表单） | 拆成 设置 首页 + 4 个二级页 | 内容按组拆开，字段不减 |
| `ModelConfigActivity`（独立 Activity，从设置进入） | 设置 → 大模型配置 | 内容承接 T9-08C-R2，视觉按新规范重排 |
| 首页状态胶囊 + 当前轮文本 | 首页状态区（orb + 状态文案 + 当前轮卡片） | 状态更多、层级更清楚 |

> 迁移原则：**能力不减、入口重排、路径唯一。** 任何页面迁移都要保证原来的功能仍能到达，
> 只是从「多个入口都能到」改成「只有一个正确入口」。

## 4. 首页：语音状态机

首页只有一个会变的东西：**当前语音状态**。九个状态全部要有明确外观，不允许出现
"看起来一样但含义不同"的画面。

| # | 状态 | 状态色 | 主文案 | 首页可做的操作 |
| --- | --- | --- | --- | --- |
| 1 | 待机 | 中性灰 | 有什么可以帮你？ | 说唤醒词；点常用技能 |
| 2 | 唤醒 | 强调蓝 | 我在 | 直接说话 |
| 3 | 正在聆听 | 青 | 我在听… | 结束收音 |
| 4 | ASR 识别 | 强调蓝 | 识别完成 | 等（自动提交） |
| 5 | AI 思考 | 琥珀 | 我在想… | 取消 |
| 6 | 正在播报 | 绿 | 正在回答 | 停止播报 |
| 7 | 播报停止 | 灰 | 已停止播报 | 继续说完 |
| 8 | 连续对话 | 强调蓝 | 继续聊（倒计时） | 直接说话 |
| 9 | 异常/中断 | 红 | 网络好像断了 | 重试 |

状态迁移（由 worker 的公开状态驱动，UI 只读不写）：

```
待机 ──唤醒词──> 唤醒 ──麦克风就绪──> 聆听 ──停顿──> 识别 ──提交──> 思考
                                                     │              │
                                     连续对话 <──── 播报完成 <──── 回答到达
                                        │              │
                                    用户沉默 8 秒      用户说「停止」──> 播报停止
                                        └──> 待机        任意状态 ──失败──> 异常
```

硬约束（沿用已验证的语音链路结论）：

1. **UI 不驱动语音链路。** 首页只读 `status.public.json` / `events/*.json` / `play.public.json`，
   唤醒、ASR、TTS 仍由原厂能力完成。
2. **停止是定向的。** 「停止播报」携带当前轮 `tts_id`（T9-08B-R2 的 `stop_targeted`），
   不允许出现"停止后重播"的画面状态。
3. **异常必须说清是谁的问题。** 后台服务掉了、模型接口不通、ASR 没听清，三者文案必须不同
   （见 `UI_DESIGN_SYSTEM.md` §9 文案规范）。

## 5. 首页之外的页面，信息密度规则

| 页面类型 | 一条区域内最多 | 说明 |
| --- | --- | --- |
| 列表页（技能 / 记忆 / 闹钟） | 一屏 6 行（行高 ≥ 56dp） | 超出滚动，不压缩行高 |
| 设置页 | 一屏 5 个分组行 | 分组之间 14dp，组内 0 间距（靠分隔线） |
| 技能功能页 | 5 个区（见扩展规范） | 不允许再套 6 层容器 |
| 对话记录 | 只读，一屏 8 行 | 没有输入、没有发送 |

## 6. 交互与返回

| 操作 | 行为 |
| --- | --- |
| 点导航项 | 切到该一级页，清空二级栈 |
| 进入技能 | 技能中心下方展开二级菜单，当前技能高亮 |
| 返回（界面按钮） | 回到直接上级（技能页 → 技能中心；设置二级页 → 设置） |
| 物理返回键 | 与界面返回完全一致；在首页时回到系统桌面而不是退出服务 |
| 二级页里的弹窗 | 返回键先关弹窗，再退页面 |
| 首页 | 永远 `singleTask`，从任何地方回首页不重建状态 |

不允许出现：返回键直接跳到首页、二级页出现"关闭"与"返回"两个意思相同的按钮、抽屉式菜单。

## 7. 与语音/模型/记忆服务的边界

| 界面需要的数据 | 来源 | 界面能否写 |
| --- | --- | --- |
| 语音状态、轮次、失败原因 | `status.public.json`（只读） | 否 |
| 每轮问答文本 | `events/<seq>.json`（只读） | 否 |
| 播报状态与 `tts_id` | `play.public.json`（只读） | 否 |
| 停止播报 | inbox `{"kind":"stop","tts_id":N}` | 是（唯一写操作） |
| 模型配置 | `files/models.json`（App 私有，明文） | 是 |
| 长期记忆 | T9-08D 的 `memory.json`（0600 root）+ IPC | 是（只经 IPC） |
| 技能开关与技能数据 | `files/skills.json` + 各技能自己的文件 | 是 |

**界面不允许**直接读 `/data/local/tmp/t5_bridge/` 下的私有状态、不允许读 worker 私有配置、
不允许在 UI 侧发起模型 HTTP 调用（模型调用只发生在 worker）。

## 8. 验收对照（本架构怎么回答审计要求）

| 审计要求 | 落地位置 |
| --- | --- |
| 一级页面明确 | §2 五项导航表 |
| 不把所有功能堆在首页 | §2 职责边界 + §4 首页只放交互与状态 |
| 首页完整语音状态 | §4 九状态表 + 原型 01–09 |
| 技能中心承载不同类型技能 | §3 页面树 + `UI_SKILL_EXTENSION.md` |
| 新增技能不改主导航 | `UI_SKILL_EXTENSION.md` §4 注册方式 |
| 长期记忆独立入口 | §2 记忆中心 + 原型 15 |
| 无文字输入、无传统会话管理 | §3 职责迁移表 |
| 导航在不同窗口尺寸下的表现 | §2 导航形态（208 → 72） |
