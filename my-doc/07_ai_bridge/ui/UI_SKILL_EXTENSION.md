# TG-Z02 技能中心与技能页扩展规范（T9-UI-01）

> 目标：**新增一个技能，只需要写它自己的功能页和配置项，不改主导航、不改首页结构、
> 不改任何已有技能的代码。** 本文就是这个"只需要"的边界定义。
>
> 闹钟、日程、音乐只是第一批验证对象；天气、导航、智能家居、信息查询、设备控制都必须
> 能沿着同一套规矩进来。

---

## 1. 技能是什么

一个技能 = **页面上的一块能力** + **一份配置** + **（可选）一个语音入口** + **一个状态**。

| 组成 | 由谁提供 | 存在哪 |
| --- | --- | --- |
| 功能页（主操作区） | 技能自己 | 代码（View 构造） |
| 技能配置项 | 技能自己声明，框架渲染 | `files/skills.json` 的 `settings` 段 |
| 启用状态 | 用户在技能中心操作 | `files/skills.json` 的 `enabled` |
| 语音入口 | worker 的 `skill_dispatch` 表 | 设备侧路由表（技能接入时登记） |
| 状态与提示 | 技能自己给一句话 | 运行时计算 |

技能**不拥有**：导航项、顶栏、返回逻辑、主题色、字体、图标绘制、状态栏。
这些由框架统一给，技能只填内容。

## 2. 技能清单（首批与规划）

| id | 名称 | 图标 | 首批状态 | 说明 |
| --- | --- | --- | --- | --- |
| `alarm` | 闹钟 | `alarm` | 已启用（示例已画完） | 列表 + 技能设置 + 新增 |
| `calendar` | 日程 | `calendar` | 已启用（示例已画完） | 月历 + 当日列表 |
| `music` | 音乐 | `music` | 待接入（骨架已画完） | 播放器 + 播放列表 |
| `weather` | 天气 | `weather` | 待接入 | 当前天气 + 预报 |
| `device` | 设备控制 | `chip` | 规划中 | 音量、亮度、蓝牙 |

## 3. 技能页的 5 个区（固定的骨架）

任何技能页都长这样，一个区都不能少，也不能多：

```
┌──────────────────────────────────────────────────────────────┐
│ 技能中心 / 闹钟                          [+ ]  [技能设置]      │  ← 顶栏（框架给）
├──────────────────────────────────────────────────────────────┤
│ ① 技能头部                                                   │
│    [已启用]  语音可用：说「明天七点叫我起床」        (开关)     │
├──────────────────────────────────────────────────────────────┤
│ ② 主操作区（本技能最重要的一个对象，占满剩余高度）              │
│                                                              │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ ③ 技能设置区（只属于本技能的参数）    ④ 状态与提示（一句话）    │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 底部操作条（本技能的主操作，右侧）                          │
└──────────────────────────────────────────────────────────────┘
```

| 区 | 内容 | 规则 |
| --- | --- | --- |
| ① 头部 | 启用状态胶囊 + 语音可用性一句话 + 启用开关 | 语音入口没接通时必须写「暂不支持语音」 |
| ② 主操作区 | 列表 / 日历 / 播放器 —— **本技能唯一的核心对象** | 占满高度，内部滚动，不得再切成多标签 |
| ③ 技能设置 | 3–6 个参数行（铃声、音量、贪睡…） | 超过 6 个就进「技能设置」二级页 |
| ④ 状态与提示 | 未接入 / 受限 / 错误 / 数据来源 | 允许为空，但"不能工作"时必须写 |
| ⑤ 底部操作条 | 主操作（新增 / 新建 / 接入） | 只有 1 个 `primary`，位置固定在右下 |

参考实现：原型 `12_skill_alarm.png`、`13_skill_calendar.png`、`14_skill_music.png`；
骨架标注见 `11_spec_skill.png`。

## 4. 接入契约（最小接口）

### 4.1 技能页面接口

```java
package com.tgz02.voice.skill;

/** 一个技能在界面上需要的全部内容。框架负责摆位置，技能只负责填。 */
public interface SkillPage {

    /** 稳定 id，写进 skills.json，之后不许改（改了等于新技能）。 */
    String id();

    String name();                       // 闹钟
    String iconName();                   // 见 UI_DESIGN_SYSTEM §5 的图标表
    String summary();                    // 一句话：说「明天七点叫我起床」就能建闹钟
    String voiceHelp();                  // 语音可用性；没有就返回 "暂不支持语音"

    SkillState state();                  // 见 §5

    /** ② 主操作区：返回一个填好的 View（高度由框架给 MATCH_PARENT）。 */
    android.view.View buildContent(android.app.Activity host);

    /** ③ 技能设置：返回 3–6 行；返回空列表表示"本技能没有可配置项"。 */
    java.util.List<SkillSetting> settings();

    /** ④ 状态与提示：一句话，null 表示不显示。 */
    String statusLine();

    /** ⑤ 底部主操作：文字；返回 null 表示本技能没有主操作（不显示底部条）。 */
    String primaryActionLabel();

    void onPrimaryAction(android.app.Activity host);

    /** 数据变化时（例如闹钟被语音创建）由技能自己刷新 ②。 */
    void refresh(android.view.View content);
}
```

```java
public final class SkillSetting {
    public final String key;        // "ringtone"
    public final String label;      // "默认铃声"
    public final String value;      // "清晨"
    public final int kind;          // TEXT / SWITCH / CHOICE
    // kind 决定点进去是对话框还是直接切换；值的读写走 SkillStore
}
```

### 4.2 注册表

```java
public final class SkillRegistry {
    public static void register(SkillPage p);       // 只在 App 启动时调用
    public static java.util.List<SkillPage> all();  // 已排序
    public static SkillPage find(String id);        // 找不到返回 null
}
```

注册总入口只有一个文件（`Skills.java`）：

```java
static void install() {
    SkillRegistry.register(new AlarmSkill());
    SkillRegistry.register(new CalendarSkill());
    SkillRegistry.register(new MusicSkill());
    // 新技能只在这里加一行
}
```

**新增技能需要改动的全部代码 = 一个新类 + 上面的一行。** 不需要改：
导航栏、首页、顶栏、主题、`AndroidManifest.xml`（技能页不是新的 Activity，是同一个宿主里的一个 View）。

### 4.3 宿主与"不读 Intent"约束

现有产品 Activity 一律**不解析 Intent**（T9-07R1 的既定结论，必须保持）。
技能页共用**一个**宿主 Activity，用进程内静态交接：

```java
SkillHostActivity.open(activity, "alarm");   // 内部：pending = "alarm"; startActivity(...)

// onCreate 里：
String id = pending; pending = null;         // 读完立刻清空，不落任何状态
```

好处：只有一个 Activity、返回栈自然、没有 Intent 解析、没有外部可调用的深层链接。

### 4.4 数据落盘

`/data/data/com.tgz02.voice/files/skills.json`（App 私有，明文，可读可改）：

```json
{
  "version": 1,
  "order": ["alarm", "calendar", "music"],
  "skills": {
    "alarm":  { "enabled": true,  "settings": { "ringtone": "清晨", "volume": 70, "snooze": 5 } },
    "calendar": { "enabled": true, "settings": {} },
    "music":  { "enabled": false, "settings": {} }
  }
}
```

规则：文件缺失 = 全部用默认值；文件坏了 = 保留上一次可用值并记一条错误（不阻塞启动）；
写盘用 tmp + fsync + rename（与 `ModelStore` 一致）。

### 4.5 语音入口

技能要支持语音，需要在**设备侧** worker 的 `skill_dispatch` 表里登记一句路由，
并在 `voiceHelp()` 里写清楚用户能说什么。

- 界面**不允许**假装支持语音：`skill_dispatch` 里没有登记，`voiceHelp()` 必须返回「暂不支持语音」。
- 语音创建的数据（如"明天七点叫我起床"）由 worker 写入，技能页通过 `refresh()` 刷新，
  界面不主动轮询 worker 私有文件。

## 5. 技能状态模型

| 状态 | 徽标 | 卡片右侧 | 主操作 | 说明 |
| --- | --- | --- | --- | --- |
| `ENABLED` | `ok` 已启用 | 开关开 | 有 | 功能可用 |
| `DISABLED` | 中性 已停用 | 开关关 | 灰（可点开） | 用户主动关闭；语音入口同时失效 |
| `UNAVAILABLE` | `warn` 待接入 | 无开关 | 「接入说明」 | 页面在、能力没有（音乐当前状态） |
| `PLANNED` | 中性 规划中 | 无开关 | 无 | 只出现在"可添加"列表 |
| `ERROR` | `err` 异常 | 开关保持 | 「重试」 | 依赖不可用（例如权限被撤） |

文案要求：`UNAVAILABLE` 必须写清"缺什么"（缺曲库授权 / 缺系统日历权限），
`ERROR` 必须写清"哪一步失败"，两者都不许只写"不可用"。

## 6. 首页的快捷入口规则

- 只展示**已启用且最近使用过**的技能，按最近使用时间倒序，最多 **3 个**。
- 第 4 个入口固定为「全部技能」（进入技能中心）。
- **未启用、待接入、规划中的技能一律不得出现在首页快捷入口**——规则即规则，
  不因"首页看起来空"而破例；数量不足就少放，不留空位、不用假按钮填充。
- 目前音乐尚未接入，因此**不得**作为可用快捷入口出现在首页（T9-UI-01 首稿原型曾违反
  此条，R1 已修正：待机/播报等状态的快捷入口只有闹钟、日程与「全部技能」）。
- 快捷块只承载"进入技能"，不承载"执行技能动作"（不做长按直接开闹钟这类隐藏手势）。
- 技能被停用后从快捷块消失；再次启用后按最近使用时间决定是否回到快捷块。

## 7. 新增一个技能的验收清单

1. 技能中心出现在正确的分组（已启用 / 可添加）。
2. 点进去是 5 区结构，顶栏面包屑为「技能中心 / 技能名」，返回回到技能中心。
3. 导航栏在技能中心下展开二级菜单，当前技能高亮，切换同级技能不叠栈。
4. 启用 / 停用立刻生效，并写进 `skills.json`，重启后保持。
5. 主操作只有一个 `primary`，位于右下，位置与闹钟/日程完全一致。
6. 设置项 3–6 个，全部能在界面上改，改完立即生效。
7. 没有语音入口时头部明确写「暂不支持语音」；有入口时写清一句示例话术。
8. 1080 宽以下（72 折叠导航）时布局不破：主操作区仍占满，文字不被截断成两个字。

---

## 8. 禁止事项

1. 不允许技能自建导航项、自建顶栏、自建返回按钮。
2. 不允许技能页出现两个以上 `primary` 按钮，或把主操作放在左下。
3. 不允许技能页套 Tab / 侧滑 / 抽屉——需要多视图就在 ② 区内部用分段控件。
4. 不允许把"技能设置"直接摊在技能中心列表页上。
5. 不允许在首页写技能专属的业务逻辑（首页只负责"进入"）。
6. 不允许为了一个技能改动 `UI_DESIGN_SYSTEM.md` 的 token。
7. 不允许新增 Activity 来表达技能页（宿主只有一个）。
