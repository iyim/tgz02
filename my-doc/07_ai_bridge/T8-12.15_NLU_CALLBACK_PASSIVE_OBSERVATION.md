## 二、观测实现（逐条对任务书 §三）

| 要求 | 实现 |
|---|---|
| 三种模式都计数 | `tg_nlp_cb` 里 PASS / DECIDE / FAILCLOSED 三条路径都调 `obs_record()`；PASS 路径**不再提前 return 之前什么都不记** |
| 每条记录字段 | 单调毫秒 `mono_ms`、墙钟毫秒 `wall_ms`、`sid`、`type`、当时的 `mode`、最终 `decision`（PASS=放行原厂 / DROP=跳过原函数） |
| 不解引用结果对象 | 函数签名收 `void *res` 但不使用；只读 `sid`/`type` 两个整数 |
| 不记录语音文本 | 记录结构里没有任何文本字段，回调里也没有任何字符串拷贝 |
| 回调内禁止 I/O/分配/日志/阻塞锁 | `extract_obs.py` 对 `obs_record` 与 `tg_nlp_cb` 两个函数体做禁用调用扫描（printf/open/read/write/malloc/pthread_mutex_lock/__android_log/…）→ **clean**；时间取 `clock_gettime`（vDSO，无系统调用） |
| 固定容量环形 + 原子序号 | `TG_OBS_CAP=256`（2 的幂），序号用一次 `__atomic_fetch_add` 分配 |
| 读不到半条记录 | 每槽自带 seqlock：写前把 `seq` 从偶数 CAS 成奇数，写完再置下一个偶数；读取方要求"前后 seq 相同且为偶数 + tick 与本条序号一致"才采纳 |
| 满时覆盖最旧 + 覆盖计数 | 覆盖由序号取模自然发生，`g_obs_overwritten` 单独计数 |
| 不改回调返回值 | 返回值仍由 `mode` 与 `t8_to_should_drop` 决定；观测只是旁路 |

另外两个细节（值得写进实现约定）：
- `g_nlu_nlp_calls` 的旧语义**没有改**（仍只在非 PASS 模式累加），否则旧的 `nlp_pass+nlp_skip+nlp_failclosed == nlp_calls` 不变量会破；"所有模式的总数"另记在 `g_obs_total`。
- 抢占不到槽位时（写者被调度器抢占）用 `yield`/`pause` 退让重试，**不睡眠、不取锁**；重试 65536 次仍失败才丢这条并记 `g_obs_contended`。

## 六、观测结果：0 条回调

三份快照（安装后、第一次播报后、音量拉满第二次播报后）都是同一行：

```
obs v=1 cap=256 total=0 release=0 skip=0 failclosed=0 overwritten=0 contended=0 ring_first=0 ring_next=0
```

`total=0` 表示补丁在位期间 `onNlpResult` **一次都没被调用**，不是"缓冲满了没取到"（`overwritten=0`、`contended=0`）。
导出通道本身是通的（头行 + 分块 + `observe_end chunks=1 lines=1`），`--nlu-status` 里也并列出现了新计数
（`obs_total=0 … obs_cap=256`），与旧字段区分清楚。

### 为什么没有回调：语音输入拿不到（见 `voice_regression.txt`）

1. 原厂 TTS 播「天猫精灵，现在几点了」两次（音量 40 / 最大 index 15），`dur=2201ms` / `2175ms` —— 设备毫无反应；
2. `tinyplay` 直开 ALSA：`cannot open device '/dev/snd/pcmC0D0p'`（Android 音频 HAL 占着主 PCM，无第二通路）；
3. logcat 实证：`AudioVoiceUIDL [SetInputStandBy]`、`AudioALSAStreamOut close() setMicGain to 1.7`、`UnconvWakeupManager feed when not started` —— mic 链路对扬声器输出做了**回声消除**，设备听不见自己；
4. 现场操作者回复"现在不方便说话"。

没有语音轮次 → 原厂 ASR 不出 final → 原厂没有 NLU 结果 → `onNlpResult` 不被调用。
同一窗口内 `events.jsonl` 仍是 617 行、末条 `seq=71`，可以互相印证。

## 十二、追加：用操作者录音去唤醒设备（2026-11-23 09:10~09:35）

操作者提供了真人录音（`D:\tgz02\OS\audio`：`唤醒词.m4a`、`现在几点了.m4a`、`今天天气怎么样.m4a`），
要求直接把声音送进设备、让它真的被唤醒。本轮把它当唯一目标试了一遍，全部手段与结果都在
`evidence/t8-12-p15/16_audio_injection_attempts.txt`，摘要如下。

| 手段 | 结果 |
|---|---|
| 原厂 TTS 播报唤醒词 ×2（音量 40 / 最大） | 播报 ok（2201 / 2175 ms），设备无反应 |
| `tinyplay` 16 kHz 单声道（dev 0/5） | `cannot set hw params: Invalid argument`（这两条 PCM 只吃 48 kHz） |
| `tinyplay` 48 kHz 立体声（dev 0/5，功放开） | 能开能写，但 `HPOUT/LINEOUT Mux = OPEN`，设备无反应 |
| 功放 `Audio Amp Playback Volume` | 原来是 **0 0（静音）**，已置 **7 7（最大）**，试验后还原 |
| **Java AudioTrack（WavPlay）** 走正常 HAL 路由 | 新建 `analysis/t8_12/p15/audio/WavPlay.java`，`app_process` 运行；连续 5 次成功，`written=979456/979456` |
| 硬件环路开关 `PCM0 O02 Switch` | 可置位，播放后仍无 asr_final |
| 采集侧对照（功放静音 vs 最大） | MRGRX 残差峰值 RMS **49 vs 49**，完全一致 → 播放音量对设备"听到的"没有任何影响 |

关键实测：
- 应用自己持有 `MultiMedia1_Capture` 与 `DL1_AWB_Record`（`Device or resource busy`），**录不到它到底听到什么**；
- 唯一能拿数据的 `MRGRX_CAPTURE` 是 AEC 参考相减之后的残差，播放期间电平不随音量变化；
- 同一时段 `events.jsonl` 从 617 → **619** 行，新增两条**真实人声**记录（09:07:50 / 09:08:17，都是"天猫精灵"），
  证明 ASR + Hook 链路本身正常，只是"设备听不见自己"。

结论：**软件侧无法把声音送进原厂 ASR**（回声消除/参考合并 + 两条 mic PCM 被应用独占）。
