## 0. 一句话结论

## 3. U10 双库绑定：真机只读读取结果

### 3.1 方法

```
base = 0x979c8000                       # 本轮 maps 里的 load bias，不是历史值
addr = base + slot                      # libsmartbox 两个 PT_LOAD: off 0x0->vaddr 0x0; off 0x1ea114->vaddr 0x1eb114
value = dd if=/proc/30807/mem bs=1 skip=$addr count=4 | od -An -tx4 -v
```

- 纯 `read()`，**没有** `PTRACE_ATTACH`，**没有**暂停任何线程，**没有**写内存。
- 每读一个值立刻与"`base` + 该符号在 `libsmartbox` 自己 `.dynsym` 里的 `st_value`"比对 —— 这构成自校验：如果槽位表错了，8 个值不可能同时命中。
- `process_vm_readv` 与 `/proc/pid/mem` 走同一个 `PTRACE_MODE_ATTACH` 检查；`/proc/pid/mem` 路径已成功且不产生任何 stop，因此未再部署 ARM32 辅助二进制（部署即等于在设备上跑新程序，本轮按任务书避免）。

### 3.2 逐符号结果（8/8 命中）

| 符号 | 槽位 | 槽位地址 | 读到的值 | 库内目标 vaddr | 判定 |
|---|---|---|---|---|---|
| `SessionProxy::onHandler` | `0x1f18d0` | `0x97bb98d0` | `0x97ae4238` | `0x11c238` | **MATCH smartbox** |
| `SessionManager::exitTalk` | `0x1f17bc` | `0x97bb97bc` | `0x97ad90e4` | `0x1110e4` | **MATCH smartbox** |
| `SessionDispatch::onNlpResultInner` | `0x1f1894` | `0x97bb9894` | `0x97ae096c` | `0x11896c` | **MATCH smartbox** |
| `SessionDispatch::onPushNlpResult` | `0x1f1898` | `0x97bb9898` | `0x97ae09ec` | `0x1189ec` | **MATCH smartbox** |
| `SessionDispatch::onRouterDetailInfo` | `0x1f17e4` | `0x97bb97e4` | `0x97ae0830` | `0x118830` | **MATCH smartbox** |

`libagmmi` 侧 8 个槽位：全部 **NOT LOADED**（无映射，无地址可算，无可读内容）。

### 3.3 判定

**绑定结果 = `smartbox`，无 split。**

- 8 个调用点/表项在 `:core` 里的实际指针都指向 `libsmartbox` 自己那份实现，没有跨库抢占；
- `libagmmi.so` 在本轮观测窗口内未被任何进程装载，因此"两份实现同时在跑"这个 R21 的前提在运行态下不成立；
- 按 `libsmartbox base + vaddr` 推算安装点地址，在本进程实例内是有依据的。

**保留的风险（未关闭，不降级）**

1. `libagmmi` 若在某条功能路径被 `dlopen(RTLD_LOCAL)`，它自己的重定位会绑定到自己那份 → split 在那一刻才出现。**"本轮没观测到" ≠ "结构上不可能"**；
2. 只核验了这 8 个符号的读取点，其它安装点未覆盖；
3. 结论只对 `pid=30807 / starttime=2467080` 有效，`:core` 一重启就必须重算 base 并重读。

## 5. 静态分析（本轮做的，与历史结论区分）

| 项 | 本轮结果 |
|---|---|
| 8 个符号的 `vaddr` | 由 `objdump -T libsmartbox.so` 直接从 `.dynsym` 取值（`onHandler=0x11c238` … `SessionManager::onNlpResultInner=0x114b98`） |
| 槽位→符号 | 由 `objdump -R` 的动态重定位表直接读出（`0x1f18d0 -> _ZN9AliAiLabs4AGUI12SessionProxy9onHandlerEPNS0_7MessageE` 等），与 T8-12.6 §5.2 的 8 个槽位**逐条一致** |
| `DT_NEEDED` | 36 项，**不含 `libagmmi`**；设备上除 `libagmmi.so` 自身外没有文件引用它 |
| `PT_LOAD` | 2 个：`off 0x0 -> vaddr 0x0`、`off 0x1ea114 -> vaddr 0x1eb114` → 运行时地址恒为 `base+vaddr` |
| 读值自校验 | 8 个读值全部等于 `base + 该符号 st_value`，反证槽位表正确 |

> 注意：T8-12.6 §5.2 表里那一列写的是"桩地址"（PLT stub，如 `0x93458`），**不是**函数实现地址；函数实现地址是 `.dynsym` 里的 `0x11c238` 等。本轮读取的是**表项里的实际指针**，所以比对基准必须是 `st_value`。
