## 1. 为什么"连接词切分"必然出错

连接词是**语法标记**，而动作边界是**语义标记**。二者在下面三种情况会脱钩：

1. 连接词出现在被引用的专名里（B、D）；
2. 连接词只是语气延续，不引入新动作（"播放，然后呢？"）；
3. 两个动作之间没有连接词（"暂停 声音小点" 靠停顿切）。

所以切分必须建立在**动作跨度**上，连接词只用来消除歧义。

---

## 2. 跨度模型（三层）

### 2.1 保护跨度（Protected Span）—— 先标出来，之后一律不切、不打分、不抽槽

| 类别 | 规则 | 例子 |
|---|---|---|
| 引用 | `《…》`、`“…”`、`"…"`、`「…」`、`『…』` | `《然后》`、`“晴天”` |
| 数量+单位 | 数字（ASCII/中文）+ `点/分/小时/度/斤/公里/块/%` | `七点`、`25%`、`2002 年的`（`年` 作为量词） |
| 时间表达 | `明天/后天/今天/周X/礼拜X` + 数字 | `明天早上七点` |
| 英文/型号 | 连续 ASCII 词 | `DJ`、`VIP`、`mp3` |
| 已有技能名 | 注册表里的 `title`（如"闹钟""日程"） | `关闭闹钟` 里的"闹钟" |

规则：保护跨度**内部**不做动作识别，但在**跨度边界处**允许动作起止。
实现方式：归一化后先扫描一遍生成 `protected[]` 区间（最多 8 个），后续匹配器跳过落在区间内的命中。

### 2.2 动作跨度（Action Span）

每个匹配器（L0 的关键词表 / L1-b 的模板）在命中时**必须同时返回 `[start, end)`**（字节偏移），
而不是现在的只返回"命中/不命中 + rule + arg"（【代码】`intent_route.c:32 ir_set()` 只写意图与 rule，
无偏移 —— 这是需要扩展的地方）。

```
ir_result {
    ir_intent intent;
    char rule[IR_RULE_MAX];
    char arg[IR_ARG_MAX];
    int  complete;
    int  span_start;   /* 新增：在归一化文本中的字节偏移 */
    int  span_end;
}
```

同一句话可以有多个动作跨度（最多 3 个，超过则整句不切）。

### 2.3 连接跨度（Connector Span）

`然后 / 再 / 接着 / 顺便 / 之后 / 顺便把 / 同时 / ，/ ,` —— 只在**两个动作跨度之间**才被当作分隔；
不在动作之间出现时（如"然后呢"）忽略。

## 3. 切分算法（失败即不切）

```
输入：norm（归一化文本）
1) 标注 protected[]：
2) 找所有动作跨度（每个匹配器返回 span），过滤掉落在 protected 内或与之交叠 >50% 的
3) 若动作跨度数 == 0 → 单动作流程（原有的 L0 → L1 → L2 → L3）
4) 若动作跨度数 > 3 → 不切；整句按"最长跨度"那一个动作处理，余下 → 残句反馈（§5）
5) 若两个动作跨度**交叠**（同一段文字被两个技能认领）→ 不切 + 仲裁：取"更具体"的
   （参数更多者胜；仍平局 → 取优先级表：控制 > 播放 > 查询），并记 l1_overlap
6) 相邻动作跨度之间若**没有**连接词、也没有停顿标记，且间隙 < 2 字 → 视为同一动作的多词命中
   （例："暂停播放" 被 pause 与 play 同时命中）
7) 分段结果：segments[i] = {span, intent, rule, arg, complete}
8) 任一段 complete=0（参数不完整）→ 该段进入槽位补全（§6），其余段先执行
```

判定"切分可靠"的三个必要条件（任一不满足 → 不切）：

- 每个动作跨度都有明确 start/end，且不交叠；
- 动作之间要么有连接跨度，要么间隔 ≥2 字；
- 保护跨度覆盖率 ≥ 该段文本的 100%（即没有"跨进引号一半"的动作跨度）。

## 4. 调度策略（5 类组合 × 三档）

### 4.1 组合分类与行为

| 组合 | 例子 | 行为（MIX-0，默认） | 播报 |
|---|---|---|---|
| 单 local | 下一曲 | 执行 1 个技能 | 技能模板 |
| 多 local（≤3） | 下一曲，再把声音…（后者非 local 时见下）| 顺序执行，合并成一句 | `换下一首，音量也小了点`（模板拼接，最多 2 个分句） |
| local + factory | 播放周杰伦的歌，然后把声音调小 | **只执行 local 段**；factory 段明确反馈未执行 | `播放周杰伦的晴天。音量那句我没法自己调，你再说一次"音量调小"` |
| local + AI | 把音乐暂停，然后讲个故事 | 执行 local，然后把**残余文本**作为一次内部 `ask` 提交（复用 inbox `kind=ask`，`ai_worker.c:1495-1512`） | `暂停了。` + 停顿 + AI 的回答 |
| factory + AI | 今天天气怎么样，顺便讲个笑话 | **整句交原厂**（原厂会答天气；笑话部分它可能忽略） | 原厂回答 + （可选）一条提示 |

### 4.2 三档策略（MIX-0/1/2）与启用条件

| 档 | local+factory 怎么处理 | 代价 | 启用条件 |
|---|---|---|---|
| **MIX-0（默认）** | 只做 local，明确告知 factory 段未做 | 用户要说第二遍 | 无（唯一零风险） |
| MIX-1 | 整句 PASS 给原厂，本地不做 | 失去本地能力（"播放周杰伦的歌"会被原厂答"我控制不了"） | 仅当 **所有** local 段都是"幂等且可重放"（音量/屏幕类）时；实际很少 |
| MIX-2 | 本地执行 local 段 + 用**工厂等价适配器**执行 factory 段 | 需要复制原厂语义（步长/映射），违反"不重复开发"的精神 | 仅限**已实测等价**的动作（目前只有音量步进），且必须 A/B：同一句话分别在"纯原厂"与"适配器"下执行，音量变化量与播报文案一致 |

**为什么默认 MIX-0**：审查意见指出"不能简单整句交原厂"，这是对的；
但另一头"本地替原厂执行"会引入"我们复制了原厂语义"的长期维护债。
两害相权，默认选"只做我们真正拥有的那段，并把没做的**说清楚**"。
MIX-2 作为可选优化，用数据决定（§4.3）。

### 4.3 MIX-2 的准入 A/B（写进测试矩阵）

| 指标 | 判据 |
|---|---|
| 音量：同一句"MIX-2 本地执行" vs "纯原厂执行" | 媒体音量变化量一致（±0） |
| 播报 | 文案不重复、不冲突（不能出现"音量已调到 40"和原厂"好的"两句） |
| 失败率 | 适配器失败率 ≤ 原厂失败率 + 2% |
| 回滚 | `mix_level=0` 立即可回 |

## 5. 残句检测与"未执行动作"的明确反馈

模型只回一个 `tool_call`（【实测】`evidence/t9-27/resp_c_multi.json`：一句话两个动作，只回 `music.play`），
**不得**假定整句完成。

```
执行完本地动作后：
  covered = 已执行动作的跨度集合
  residual = 全文中"能被任一匹配器命中、但不在 covered 内"的跨度
  若 residual 非空：
      residual_count++
      在回话后追加一句固定文案（见下表），并记录 residual 文本到 skill_ctx.last_residual
```

| 残余类型 | 追加文案（写死，不交给模型） |
|---|---|
| factory 类 | `后面那句（%s）我没法自己调，你再说一次就行` |
| local 类（未执行，如超出 3 段） | `还有一句（%s）我没做，再说一次吧` |
| AI 类 | 不做提示，直接作为 `ask` 提交（§4.1） |
| 无法判定 | `我只做了前面那件事` |

原则：**宁可多说一句"我没做"，也不能让用户以为做了。**

## 6. 槽位补全状态机

```
判定出技能 S，但 required 参数为空或非法
   │
   ├─ 已有 pending_slot 且 session 相同 → 用本次全文填该参数（不再追问）
   │
   ├─ 无 pending → 播报 sk_desc.clarify（每技能一句，来自清单）：
   │       music.play  : "你想听谁的歌？"
   │       volume.set  : "调到多少？"
   │       alarm.set   : "几点？"
   │     写 pending_slot{skill, param, session, deadline = now + 8 s}
   │
   ├─ 8 s 内没等到 → 丢弃 + expired_slot++（不跨会话沿用）
   └─ 等到且校验通过 → 执行 → 清 pending
```

三条铁律：

1. **不猜默认值**（`volume.set` 缺数字绝不默认 50 —— 这条是 T7-05-R1 用真机事故换来的，
   【代码】`intent_route.c:48-68` 的 `IR_TAIL_DANGLING` 与 `complete=0` 机制必须保留）；
2. **只追问一次**；第二次仍不完整 → `我没听懂这句` 并结束（不再循环）；
3. **槽位与 session 绑定**，换 session 一律丢弃（避免"上一句话的数字"污染下一句）。

## 7. 上下文续接（skill_ctx）

`conv_context` 管"说过什么"，不知道"设备在干什么"。审查意见 §四 的"刚才那首歌再放一次"
必须靠后者。

```json
{"v":1,"seq":88,
 "now_playing":{"track":"晴天","artist":"周杰伦","playing":true,"pos_ms":41000},
 "volume":50,
 "last_skill":"music.play","last_args":{"query":"周杰伦 晴天"},"last_ms":1795876070000,
 "pending_slot":null,
 "last_residual":""}
```

| 用途 | 规则 |
|---|---|
| 续作词（"再/又/还/那个/刚才/这首"）触发上下文解析 | 只有存在 `last_skill` 且 5 分钟内 → 用 `last_args` 补全槽位 |
| 注入 L2 的摘要 | ≤120 字：`正在播放：周杰伦-晴天（第 41 秒）；音量 50` |
| 注入 L3 的摘要 | 同（可选，`skill_ctx_inject=0` 可关） |
| 写入时机 | 技能执行成功后（worker 内），原子写 |
| 隐私 | 只放结构化字段；不放用户原话、不放记忆条目 |

【实测】T9-27 用例 i（"那个再放一遍"）在无上下文时报"不确定您指的是哪一首"，
有上下文后应命中 `music.ctrl(replay)` 或 `music.play(query=last)`。

## 8. 失败反馈文案表（与 SECURITY §3 的七步校验对应）

| 情况 | 文案 | 是否回落模型 |
|---|---|---|
| 参数缺失 | 技能的 clarify 句 | 否 |
| 参数非法（类型/范围/枚举） | `这个参数我听不懂，再说一次？` | 否 |
| 业务失败（搜不到） | `没找到「%s」，换个说法？` | 否 |
| 技能未实现（不该发生） | `这个我还不会` | 否 |
| 环境不可用（服务没起来） | `播放器现在没起来，等一下再说` | 否 |
| 超时 | `这次没成功，再说一次吧` | 否 |
| 归属降级（C2/C3/C4 不满足） | 本地不说话，交原厂 | — |
